# Lumi 课程语料格式契约

## 目的与适用范围

本契约供 Lumi 鹿鸣的课程知识库编纂与摄取使用。每个条目只服务一门课程、一个明确问题；学理内容与软件工作流分别成条，避免把“为什么这样设计”与“软件怎么操作/哪里出错”混成同一段回答。

条目应帮助 Lumi 按导师品格回应：先追问学生已有的意图、证据或尝试，再提示检查路径，最后才给局部示范。它不是作业代做模板，也不恢复旧有强制限制。

## 文件与目录

```text
data/courses/
  FORMAT.md
  <课程目录>/
    <三位序号>-<英文短名>.md
```

课程目录使用现行课程名的稳定英文转写或既有目录名；正文与面向师生的标题必须使用 `CONTEXT.md` 的术语。

## Frontmatter 字段规则

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `课程标签` | 是 | 必须是 11 门核心课程中的现行课程名。 |
| `内容类型` | 是 | 只能是 `学理内容` 或 `软件工作流`。学理课也可收录软件工作流。 |
| `标题` | 是 | 用学生能检索到的问题或学习目标表述，不用旧产品名、等级或门禁术语。 |
| `来源出处` | 是 | 写到可追溯的具体材料，如“旧课程设计文档”或用户提供材料的文件名/页码；未提供教材时必须如实标注。 |
| `来源类别` | 是 | 例如 `官方资料`、`教师课程材料`、`旧课程设计文档`、`公开设计常识`。该字段解释材料性质，不替代可信度。 |
| `可信度` | 是 | 只能是 `官方事实` 或 `教师经验`。一条只选一种，不能混写。 |
| `事实边界` | 是 | 说明该条能断言与不能断言的范围；软件版本、设备、参数或尺寸没有来源时不得编造。 |
| `适用问题` | 是 | 至少两条学生自然会问的表达。 |
| `关键词` | 是 | 2–6 个，优先使用词汇表术语。 |

## 可信度与来源的判定

- `官方事实`：可回溯至官方文档、课程标准或用户提供的可核验原始材料。正文只陈述该来源能够支持的事实。
- `教师经验`：教师的教学策略、案例观察、公开设计常识的课堂化转述，或旧课程设计中可回收的教学法。正文应以“可先尝试”“通常可检查”等条件性措辞表达，不伪装成硬规范。
- 同一主题同时需要官方事实与教师经验时，拆成两条，通过链接或关键词关联，绝不在一条里混写。

## 正文规则

1. 每条依次包含 `核心内容`、`导师可先追问`、`提示与局部示范`、`常见误区与证据`、`使用边界`、`术语待议` 六个小节。
2. `导师可先追问` 至少给出两句可直接使用的追问；`提示与局部示范` 只能给局部、可验证的动作，不给可直接提交的完整作品方案。
3. 软件工作流必须要求可观察证据（截图、参数、节点/图层名称、输入值或错误信息），并区分已确认事实、待验证假设和下一步动作。
4. 预置的演示内容在正文与文件中均标注“预置”；不得写成真实学生数据或真实课堂成效。
5. 发现术语缺口时，在该条末尾 `术语待议` 小节原样记录，不创造新术语替代它。

## 术语待议

- 旧课程设计中的“六元交互逻辑”在现行词汇表中没有可直接沿用的新名称，且“六元交互逻辑卡”已列为避免使用的旧形态。本语料暂只以“六项澄清”描述其内容，不为其另起名称；是否纳入结构化会诊的正式命名，待用户在会诊框架提案定稿时决定。
