# “触映”真实试用协议

## 目的

用少量真实学生验证 Agent 是否帮助学生更快识别问题、选择正确下一步并完成迁移。试用不用于证明大规模教学成效，也不把演示账号、自动化测试或教师代操作记为真实学生数据。

## 建议样本与时间

- 第一轮：5—8 名上过数字交互文创课程的学生，每人 20—30 分钟；
- 第二轮：条件允许时增加 5—8 名未完成相关案例的学生；
- 由任课教师或助教现场观察，但不代替学生点击、回答或提交证据；
- 书籍设计微闭环可邀请 3—5 名学生做可迁移性验证，与数字交互结果分开报告。

## 创建本轮专用试用班

每一轮使用单独的真实试用班，避免长期教学班的旧记录混入“本轮试用”。在安装了本机服务的电脑上执行：

```powershell
$env:PILOT_CLASS_NAME="触映真实试用 第一轮"
$env:PILOT_PARTICIPANT_COUNT="8"
pnpm pilot:prepare
```

命令默认读取当前本机常驻服务的数据库，而不是工作树里的开发库；它会创建 64 课时课程结构、真实试用任务和指定数量的预签发匿名编号。学生首次登录后自动建立 `DIAGNOSTIC` 项目。完整班级码与匿名编号只写入 `%LOCALAPPDATA%\ChuyingAI\pilot\` 下的私有访问文件，终端只显示文件路径，不输出凭据。命令还会生成一份 01—N 预编号匿名观察包；观察包只保存与私有访问文件对应的序号，不复制完整身份码。每名学生只发一个编号，不要把访问文件加入 Git、截图、录屏或比赛材料。

如果试用班已经创建、只需要为既有班级补生成匿名观察包，不得再次运行 `pilot:prepare`。使用相同班名和人数执行：

```powershell
$env:PILOT_CLASS_NAME="触映真实试用 第一轮"
$env:PILOT_PARTICIPANT_COUNT="8"
pnpm pilot:observation
```

该命令不读取或修改数据库，也不生成新的学生身份码，只在 `%LOCALAPPDATA%\ChuyingAI\pilot\` 下新增观察包文件。

## 开场前一键预检

发放任何编号前，必须使用本轮班名、预期人数和本轮公网地址执行：

```powershell
$env:PILOT_CLASS_NAME="触映真实试用 第一轮"
$env:PILOT_PARTICIPANT_COUNT="8"
$env:PILOT_PUBLIC_URL="https://本轮实际公网地址"
pnpm pilot:preflight
```

预检只读生产数据库和本机私有材料，检查64课时课程结构、任务、身份码签发/认领一致性、学生与项目对应、访问文件编号数量、观察包数量与脱敏、本机健康门和公网HTTPS。它不会输出班级码或学生身份码。只有命令退出码为0、`status` 为 `READY_TO_START`（尚无人登录）或 `PILOT_IN_PROGRESS`（已有学生开始），且8项检查全部通过时才能继续；`NOT_READY` 时先修复失败项，不得向学生发放凭据。

只有在没有本机常驻服务、明确要给项目环境创建隔离试用班时，才临时设置 `PILOT_USE_PROJECT_ENV=true`。正式试用前应在教师端确认新班级已出现在当前公开服务中；若没有出现，不得继续发放编号。

本轮报告只能选择这个专用试用班。若误用长期班级，应停止导出并重新创建专用试用班，不能人工删减旧数据后冒充系统汇总。

## 任务

### 数字交互

给出“声音已有数值但画面不动”的故障工程或等价截图。学生需要：

1. 向 Agent 描述问题；
2. 解释自己认为故障位于哪一层；
3. 确认或拒绝 Agent 行动；
4. 提交至少一条阶段证据；
5. 说明修复后如何迁移到另一种输入或输出。

### 书籍设计

给出校园社区活动素材。学生需要：

1. 完成受众/任务诊断；
2. 形成 8 页阅读路径；
3. 保存并恢复草稿；
4. 将受众从新生迁移为社区居民；
5. 提交版面证据并解释保留与改变的结构。

## 记录指标

| 指标 | 记录方式 | 解释边界 |
| --- | --- | --- |
| 任务是否完成 | 完成 / 部分完成 / 未完成 | 不把打开页面算完成 |
| 首次下一步是否正确 | 教师预先标注后与学生首个行动比较 | 记录教师标注依据 |
| 需要提示级别 | 0、1、2、3 级 | 级别越低不必然代表理解更深 |
| 修正次数 | 学生改变故障层、节点关系或页面层级的次数 | 区分主动修正与教师代改 |
| 迁移质量 | 课程包量规＋教师复核 | 保留机器原判断 |
| Agent纠正率 | 教师确认 / 纠正 / 需要复核 | 分课程包报告 |
| 学生认知参与 | 观察学生是否提出假设、比较证据、解释关系 | 不用“停留时长”替代理解 |
| 主观体验 | 结束后 3 个短问：哪里有帮助、哪里误导、下一次会否使用 | 保留原话并脱敏 |

## 数据边界

- 真实试用使用 `REAL`，演示账号保持 `DEMONSTRATION_DATA`；两类数据不得合并计算。
- 使用匿名编号，不收集姓名、手机号、学号或与试用无关的信息。
- 截图、录音或作品材料需事先说明用途并取得同意；不同意不影响学生参加课程。
- 报告只汇总必要指标。引用学生原话时删除可识别个人的信息。
- 不保存模型内部推理；只保存问题、回答、来源、行动、执行结果和教师复核。

## 教师标注流程

1. 试用前为每个故障/任务写下可接受的下一步和判断依据；
2. 试用后在教师端查看 Agent 原判断，不先改写原记录；
3. 选择确认、纠正或需要复核，并写一句可操作原因；
4. 由第二位教师抽查争议样本；
5. 将失败问题加入固定评估集，再修规则、知识或提示词。

每名学生使用 [真实试用匿名观察表](templates/pilot-observation-sheet.md) 单独记录。匿名观察表与系统导出的班级汇总分开保存：前者证明现场观察，后者证明系统内行为，两者不能互相替代。

## 报告模板

只在真实试用完成后填写：样本人数、任务、完成率、首次下一步正确率、教师纠正率、迁移通过率、典型失败问题和学生匿名反馈。样本量较小时使用“本轮试用中观察到”，不使用“显著提升”“普遍有效”等统计性结论。

教师登录课堂学习驾驶舱、选定班级后，可点击“导出真实试用报告”。导出的 Markdown 文件强制只汇总 `REAL` 数据，自动列出 Agent 回合、来源覆盖、行动卡、学习证据、迁移、书籍设计提交和教师复核；不包含学生编号、别名、问题原文、证据原文或教师备注。

导出文件中的“任务是否真实完成”“首次下一步是否正确”“学生认知参与”“学生主观体验”固定显示为“待人工观察”。教师必须依据现场记录补填，不能把项目阶段、停留时长或页面打开记录当作这些指标的替代证据。建议使用流程：

1. 试用前完成故障任务的可接受下一步标注；
2. 试用后先在教师端完成 Agent 与学习证据复核；
3. 导出真实试用报告；
4. 将匿名观察表中的四项人工指标补入比赛材料；
5. 由第二位教师抽查纠正样本和典型失败问题。

## 停止条件

出现以下任一情况立即停止该学生试用并记录：身份或数据类型错误、他人记录串入当前会话、行动未经确认自动执行、来源与课程资料不一致、教师无法查看原判断、敏感信息出现在日志或界面。
