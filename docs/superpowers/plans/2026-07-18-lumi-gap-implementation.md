## 工作方式（Codex 必守）

1. **一个任务一个提交序列**，按依赖顺序执行；每个任务完成时金标准集必须全绿再进入下一个。
2. **术语纪律**：代码命名、UI 文案、提示词一律使用 CONTEXT.md 的术语；发现术语冲突不要自行发明，在任务产出里记录待用户裁决。
3. **导师品格贯穿**：所有涉及提示词的任务，默认苏格拉底式（追问→提示→示范），学生坚持要完整答案时给出但附理解检查。任何输出不得虚构确定性。
4. **对账义务（重要）**：本计划基于提交信息与 spec 推断能力现状，未逐文件核对实际代码（编写计划时源码工作区不可读）。**Task 0 要求 Codex 先对账**，若实际代码与计划假设不符，以实际代码为准并在计划文件中修订标注。
5. 演示相关内容（预置数据、案例）必须标注"预置"，不与真实数据混淆。

## Task 1：课程注册表与知识库课程化

**前置**：Task 0。这是后续一切的地基。

- [ ] 建立课程注册表：11 门核心课程（清单见 spec §4），每门含：课程名、主导属性（学理课/软件课）、嵌入软件（如 IP 形象设计→Blender，数字交互文创→TouchDesigner）
- [ ] 知识库按课程分域：语料条目挂课程标签，检索按学生当前课程上下文过滤加权（跨课程仍可召回，但当前课程优先）
- [ ] 每门课语料同时收录两类内容：学理内容与该课所涉软件工作流（对应双面孔的两类问题）
- [ ] 学生会话携带"当前课程"上下文（入口选择或对话中推断，允许切换）
- [ ] 内容编纂优先级：数字交互文创设计（主线课，旧 spec 的 TD/DigiShow 排查链与案例全部回收入库）与版式设计（切课时刻目标课）先行，其余 9 门先建骨架
- [ ] 金标准集新增：同一问题在不同课程上下文下检索来源正确的用例

**验收**：以"数字交互文创"与"版式设计"两种课程上下文提问同一问题，召回来源明显分课；旧 TD 排查链内容可被检索到且带来源标注。

## Task 2：配置台（轻教师台·上）

**前置**：Task 1。这是"换魂"机制，也是演示切课时刻的主角。

- [ ] 教师身份入口与权限隔离（教师/学生两角色，沿用现有会话机制扩展）
- [ ] 教师可创建/选择课程，上传课程资料（文本、教案、案例文档），入库为该课程语料，处理进度可见
- [ ] 上传→可检索的延迟控制在演示可接受范围（切课时刻要求 30 秒内导师"换魂"生效；若全量索引慢，做增量/优先索引）
- [ ] 资料可查看、可删除；删除后检索即不再召回
- [ ] 金标准集新增：上传一份新课程资料后，导师能引用其内容且标注来源

**验收**：现场演示路径可走通——教师上传版式设计资料，返回学生端提问版式问题，Lumi 引用新资料回答，用时符合演示节奏。

## Task 3：结构化会诊

**前置**：Task 1（课程上下文）。复用已有作品图理解能力。

- [ ] 会诊框架机制：框架维度按课程可配置，随课程注册表存储；实现默认框架（下方五维一收），教师可在配置台覆盖
- [ ] **默认框架：五维一收（已于 2026-07-18 定稿，定义见 `CONTEXT.md` 的"会诊五维"与"收束"）**——观察五维：①目标 ②创意转译 ③构成与层级 ④形式语言 ⑤工艺与规范；外加每次必到的收束（亮点 + 下一步，联动成长档案对比该生上次会诊）。收束**不是第六个维度**，是横跨五维的收尾结构，实现上需保证只深谈 1–2 维时它仍然输出
- [ ] 学生上传作品图触发会诊：输出按维度结构化呈现（非自由散文），每维含观察依据（引用画面中可见的事实），语气遵守导师品格
- [ ] 会诊结果写入成长档案（供第⑥维与洞察台使用）
- [ ] 软件类问题不走会诊框架，走证据式排错（现有能力，确认双面孔切换正确）
- [ ] 金标准集新增：典型作品图的会诊输出结构完整、维度不缺失、无凭空断言；同图重复会诊结论稳定

**验收**：上传一张海报草图，得到六维结构化点评，其中"亮点与改进"能引用该生历史会诊；上传一张 PS 报错截图，走排错而非会诊。

## Task 4：举一反三动作

**前置**：Task 3（会诊完成是主要触发点）。

- [ ] 触发时机：会诊判定作品基本完成、或学生明确表示完成时，导师主动抛 1 个变式练习（不刷屏，一次一个）
- [ ] 变式生成维度：换媒介、换场景、换受众、换输入方式（交互课），基于当前作品与课程上下文生成，附"哪些设定要变、哪些保留"的追问
- [ ] 学生可回应或跳过；回应内容进入成长档案（迁移能力信号）
- [ ] 金标准集新增：给定完成态作品上下文，变式练习切题、只改一两个条件、附结构化追问

**验收**：演示主线用例可走通——交互作品完成后，Lumi 抛出"距离触发换成声音触发，逻辑哪里要改？"式变式并追问。

## Task 5：依赖度信号

**前置**：Task 0（可与 Task 1–4 并行）。

- [ ] 定义并采集会话级信号：求助频次、请求完整答案的次数、示范级帮助占比、理解检查通过情况（口径写入代码注释与本文件，不进 CONTEXT.md——属实现细节）
- [ ] 信号按学生×课程聚合存储，供洞察台使用；对学生本人不展示（避免标签化），符合成长档案可见性规则
- [ ] 金标准集新增：构造高/低依赖两组模拟会话，聚合结果方向正确

**验收**：模拟数据下，依赖度聚合值可查询且方向符合预期。

## Task 6：洞察台（轻教师台·下）

**前置**：Task 2（教师入口）、Task 3/5（数据来源）。

- [ ] 共性困难聚合：按课程聚合学生提问主题与会诊高频短板维度，呈现"哪些概念反复被问、哪类问题最多"
- [ ] 依赖度概览：班级分布与显著偏高个体（呈现给教师，措辞中性）
- [ ] 重讲建议：基于共性困难生成下次课建议（标注为 AI 建议，教师自行判断）
- [ ] 只呈现可行动信息；不做聊天字数、登录次数等虚荣指标（CONTEXT.md 红线）
- [ ] 金标准集新增：给定模拟班级数据，聚合结果与建议可复现、不虚构

**验收**：预置班级数据下，教师登录可见共性困难、依赖度概览、重讲建议三块，且全部可追溯到原始数据。

## Task 7：演示装配

**前置**：Task 1–6 全部。

- [ ] 预置演示数据（全部标注"预置"）：一名演示学生（数字交互文创课，含成长档案历史）、一个班级（洞察台数据）、版式设计课资料包（配置台现场上传用）

- [ ] 公开访问：HTTPS 链接 + 二维码 + 演示账号，无特殊配置浏览器可用
- [ ] 模型服务失败降级路径演练：知识库检索与检查清单仍可用

**验收**：按演示脚本从头到尾走一遍（含降级演练），全程无需口头解释、无死角。
