## W1：三轨集成（**最高优先，且现在就该动**）

### 风险为什么真实

前端对 mock 开发时一切顺滑：数据即时返回、没有错误态、没有网络延迟。而真实后端在**洛杉矶**（175–400ms），模型首字要 **12 秒**，作品图跨太平洋上传要十几秒。**这些差异会在集成当天集中爆发**，而那时通常已经没有时间了。

### 原则：不要等全部做完再合

- [x] **单端点即时接入**：学生端主路径已按真实 API handler 契约逐端点接入，并保留 mock 回退
- [x] `NEXT_PUBLIC_USE_MOCK` 支持**按端点粒度**切换，而非全局一刀切
- [x] 契约文档 `docs/frontend/api-contract.md` 是**唯一真源**，前后端共享会诊运行时契约

### 按演示路径排集成顺序

评委会按这个顺序碰到系统，所以按这个顺序合：

1. **入口/会话**（班级码、演示身份）→ 没有它后面全走不通
2. **对话主界面 + 流式**→ 门面
3. **作品上传**→ 跨太平洋，最容易出问题
4. **五维会诊展示**→ 核心价值
5. 成长档案 → 举一反三 → 教师侧

### 真实延迟下的验收（**不要用 mock 验收**）

- [ ] 每接入一个端点，**在真实延迟下**过一遍：加载态是否出现、是否明确、会不会被误认为卡死
- [ ] 作品上传必须有**进度反馈**；12 秒的模型首字延迟必须有**"正在思考"的可感知反馈**，否则学生会重复点击
- [ ] 流式中断、模型不可用、上传失败三种异常各走一次，确认降级提示**体面且诚实**
- [ ] 记录每条路径的真实耗时，写入 `docs/runbooks/`——这些数字后面写报告要用

**验收**：演示主路径在真实后端下端到端跑通，且每一步的等待都有明确反馈。
