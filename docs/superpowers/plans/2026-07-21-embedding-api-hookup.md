## Task 1：确认现网 `/embeddings`（免新密钥的最短路径，先做）

- [ ] 用**实际生效**的 baseUrl 与密钥（以 `service.env` 为准，注意 7-19 曾有 `.env.local` 指向另一台服务器的配置矛盾）直接调 `/v1/embeddings`，测网关支持的常见中文可用模型名
- [ ] 可用 → 配置启用向量检索，跳到 Task 3；不可用 → 记录确切报错，进 Task 2 + 文末 DECISION NEEDED

## Task 2：嵌入配置解耦（夜间队列 T5 原任务，代码部分）

- [ ] 新增 `LLM_EMBEDDING_BASE_URL` / `LLM_EMBEDDING_API_KEY`（可选；不填回落对话那套配置）
- [ ] `env.ts` 校验允许嵌入独立成组；`orchestrator-context.ts` 使用嵌入专属配置
- [ ] 三种组合（全回落 / 独立 URL / 独立 URL+KEY）各一个单测
- [ ] ⚠️ 只做代码解耦，**不选提供商、不填密钥**——那是 DECISION NEEDED

## Task 3：检索链路端到端验证

- [ ] 抽 2–3 门已有语料的课程（如版式设计、数字交互文创设计），每门 2–3 个典型学生问题，确认：检索命中知识库、回答引用来源正确
- [ ] 把命中情况（哪门课、命中/未命中）简要记录进本文件末尾，供明天测试对照

## Task 4：降级行为确认（无论 Task 1 结果如何都要做）

- [ ] 实测"嵌入不可用"时对话的行为：必须是**静默降级、对话照常**（跳过向量检索或退化为关键词），**不允许报错阻断对话**；若现状会阻断，修为静默降级并在日志记明
- [ ] 若明天测试将处于降级态，在本文件与待用户清单显著标注："当前知识库检索为降级态，测试结论不代表最终检索质量"

## DECISION NEEDED（仅当 Task 1 确认现网不可用时需要用户拍板）

> 嵌入提供商三个候选，判据不变（OpenAI 兼容 `/embeddings`、中文效果好、LA 服务器可访问）；选定后用户提供密钥：
>
> 1. **OpenAI `text-embedding-3-small`**——LA 服务器访问最顺、最稳；中文效果够用不顶尖；成本低
> 2. **SiliconFlow（BGE-M3）**——中文检索效果最好、便宜；但服务在国内，**LA 服务器反向访问延迟/稳定性需实测**
> 3. **阿里 DashScope `text-embedding-v4`（OpenAI 兼容模式）**——中文好；同样有 LA 反向访问问题，且需国内账号
>
> 推荐顺序 1 → 2：先保"稳定可用"，中文效果赛后可换（换嵌入模型需重建知识库向量，语料量小、重建成本低）。

2. 嵌入三种 env 组合单测绿；配置来源单一明确（不复现 `.env.local` vs `service.env` 的矛盾）
3. 检索命中记录已附于本文件
4. 对话在嵌入故障下不阻断
