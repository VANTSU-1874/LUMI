## 硬约束（并行不撞车的保证）

1. **独立 worktree 与分支**：从 main 新建 `feature/lumi-content` 分支及其 worktree，全程在其中工作，不进入重建会话的工作目录。
2. **路径白名单**：只允许创建/修改 `data/**`、`docs/runbooks/**`、`docs/competition/**`、`docs/superpowers/**` 下的文件。白名单之外一律不碰。
3. **格式契约先行**：所有内容产出使用本计划 Task P1 定义的语料格式，保证主线 Task 1 能直接摄取，不需要返工。
4. **术语纪律**：文案与文件命名使用 CONTEXT.md 术语；发现术语缺口，记录到产出文档末尾"术语待议"小节，不自行发明。
5. **需要用户供给的材料**（教案、课件、历届作业），在对应任务下列出清单请用户投放到指定目录，缺料时跳过该项继续后面的任务，不阻塞。

## 子代理授权（2026-07-18 追加）

本计划**允许使用子代理**，但按"有无模板可照"划线——内容工作的头号风险是文风漂移，而导师品格正是 Lumi 的核心卖点。

**可委派**（批量、可并行、有模板可依）：
- P1 语料条目撰写：**在 `FORMAT.md` 与首批参考样例定稿之后**，按课程或主题分片委派
- P5 比赛通知附件的文本提取与要点摘录

**不可委派**（定调物，需一致文风、一人成篇）：
- P1 的 `FORMAT.md` 格式契约本身与首批参考样例
- P2 会诊框架提案——其中的示例点评语句是导师品格的定调物
- P3 演示脚本细稿
- P5 申报报告初稿与评审标准对齐备忘

**委派时必须**：
1. 把 `CONTEXT.md`、`FORMAT.md`、参考样例三样随任务一并交给子代理——子代理不继承主会话上下文，缺任何一样必然跑偏；
2. 子代理同样受路径白名单与"禁止修改应用代码"约束；
3. 子代理不得决定任何"待用户决策"事项，遇分歧回报主会话；
4. **主会话负责收口**：所有子代理产出在提交前，由主会话按 `CONTEXT.md` 术语与导师品格逐条校订，文风不一致的重写而非照收。

## Task P1：语料格式契约与两门优先课编纂

- [ ] 定义语料条目格式（Markdown + frontmatter 或 JSON，Codex 按主线 Task 1 的摄取需求自行设计并写成 `data/courses/FORMAT.md`），字段至少含：课程标签、内容类型（学理内容 / 软件工作流）、标题、正文、来源出处、可信度（官方事实 / 教师经验，两者不得混写）
- [ ] **数字交互文创设计**（演示主线课）：从旧 spec（已取代的 2026-07-11 文档）回收 TD/DigiShow 信号链排查内容、六元逻辑案例场景，改写为符合格式的语料条目；来源标注"旧课程设计文档"
- [ ] **版式设计**（切课时刻目标课）：编写栅格、字体、层级、留白等基础学理条目与常见错误条目；来源可标注公开设计常识或用户提供的教材，逐条注明
- [ ] 其余 9 门课：只建骨架目录与空清单文件，列出每门课需要用户供给的材料清单

**验收**：`FORMAT.md` 存在且自洽；两门优先课各有一批可摄取的语料条目；`INTAKE.md` 清单明确。

**验收**：提案文档完整，两门课变体齐全，示例语句符合导师品格。
