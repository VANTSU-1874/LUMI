# 模型 A/B 测试协议（内容轨道选型）

**目的**：在把整条内容轨道（P1–P5）交给某个模型之前，用一个小而完整的真实任务，实测候选模型（如 GPT-5.6 Sol Ultra vs Terra Ultra）谁更适合 Lumi 的中文教学内容写作。协议与具体型号无关，任何两个候选都适用。

**为什么实测而不是看参数表**：这条轨道考验的是中文文风、导师语气、守规矩程度——这些在模型卡上看不出来，跑一次就见分晓。

**成本**：一个小任务 × 2 次，很便宜。不要用整条轨道做 A/B。

---

## 被测任务：Task P2（会诊框架提案）

选它的理由：小而完整（一份文档）、纯写作、质量肉眼可辨；而且它是"不可委派"的定调物——**恰恰是模型强弱最要紧的那类活**。

任务定义见 `2026-07-18-lumi-parallel-content-plan.md` 的 Task P2。

## 公平性要求

1. **两次运行起点一致**：同一 main 提交，各自**全新会话**（不复用上下文、不互相可见）。
2. **提示词逐字相同**：用下方"统一启动指令"，一字不改地喂给两个候选。
3. **输入材料相同**：`CONTEXT.md`、Lumi 设计说明、内容轨道计划——三份都给，不多不少。
4. **输出隔离**：分别写到 `docs/experiments/critique-framework-variant-A.md` 与 `variant-B.md`，互不覆盖。
5. **盲评**：哪个变体对应哪个模型，写在 `docs/experiments/AB-KEY.md`，**打分完成前不要打开**。

### 统一启动指令（逐字复制给两个候选）

> 阅读 `CONTEXT.md`、`docs/superpowers/specs/2026-07-18-lumi-design-tutor-design.md`、`docs/superpowers/plans/2026-07-18-lumi-parallel-content-plan.md`，然后执行该计划的 Task P2（结构化会诊框架提案），输出写入 `docs/experiments/critique-framework-variant-<X>.md`。严格遵守计划中的路径白名单、术语纪律与"待用户决策事项只出提案不拍板"的约束。不要修改任何其他文件。

## 评分表（各项 1–5 分，加权满分 45）

> 权重合计 9 个单位（三项 ×2 + 三项 ×1），故加权满分为 45。

| 维度 | 看什么 | 权重 |
| --- | --- | --- |
| **中文文风** | 像中国设计教师说的话，还是翻译腔、AI 腔 | ×2 |
| **导师品格** | 示例点评语句是否真做到"先追问→再提示→后示范"，而不是直接给结论 | ×2 |
| **专业准确度** | 栅格、字体、层级、留白等术语用得对不对；交互课的内容是否外行 | ×2 |
| **术语纪律** | 是否严格使用 CONTEXT.md 术语，有没有自己发明词 | ×1 |
| **守规矩** | 有没有越出路径白名单、有没有替用户拍板（应当只提案并标注待定） | ×1 |
| **结构完整** | 六维 × 两门课变体是否齐全，每维检查要点与 2–3 条示例语句是否到位 | ×1 |

## 判定规则

1. 总分高者胜出，用它跑完 P1–P5。
2. **分差在 5 分以内（45 分制）视为平局**——此时选更便宜或更快的那个（内容轨道 token 量大，性价比比微弱质量差更重要）。
3. **两项否决条件**（任一触发直接淘汰，无论总分）：越出路径白名单改了不该改的文件；替用户拍板了"待用户决策"事项。
4. 结论与评分记入 `docs/experiments/AB-RESULT.md`，含胜出理由与两份变体的差异摘要，供后续换模型时参考。

## 执行方式（二选一）

- **手动**（推荐，最干净）：在 Codex 里选模型 A 开一个新会话跑一遍，换模型 B 再开新会话跑一遍。
- **委派**：若 Codex 支持给子代理指定模型，可由主会话派两个子代理分别执行——但两个子代理必须拿到完全相同的输入与提示词，且主会话不得在中途干预任一方的产出。

## 事后

胜出模型确定后，内容轨道计划照常从 Task P0 执行。两份变体文档保留在 `docs/experiments/` 作为记录，其中胜出的一份可作为 Task P2 的初稿继续打磨——**不要浪费，但也不要直接当定稿**（P2 仍需用户定稿）。
