## 为什么前端是高风险高回报项

评委是设计教师。他们会用 Lumi 评学生作品的那套标准来看 Lumi 自己的界面——**Lumi 一边点评学生"信息层级不清楚"，一边自己界面混乱，作品当场失去可信度**。

因此本轨道的验收标准不是"功能能用"，而是：**这个界面本身经得起五维会诊**（目标清楚、层级稳定、形式统一、工艺规范）。

对应评分：用户体验 15 分是直接项，但界面质量会连带影响创新性与教学应用的观感。

## Task F0：契约冻结与 mock 层（**最先做，这是并行的前提**）

前端等的不是"功能做完"，而是"接口形状定下来"。本任务把形状定死，之后前端可以完全脱离后端进度开发。

- [ ] 盘点现有 API：读 `app/api/**` 所有路由，记录每个端点的请求/响应形状，写成 `docs/frontend/api-contract.md`
- [ ] 补写尚不存在的端点契约（后端还没实现，但形状先定）：
  - **五维会诊结果**：按 `2026-07-18-critique-framework-proposal.md` §2.4 的配置骨架——五个维度 `goal`/`translation`/`structure_hierarchy`/`formal_language`/`craft_standards`，外加独立的 `closure`（**收束不是第六维，前端也不许把它渲染成第六个并列卡片**）
  - **课程注册表**：课程列表与当前课程切换
  - **配置台**：资料上传、列表、删除
  - **洞察台**：共性困难、重讲建议（S5 可能被裁，契约先留）
- [ ] 建 mock 层：所有契约提供假数据，前端组件全部对 mock 开发，`NEXT_PUBLIC_USE_MOCK` 开关切换真假后端
- [ ] 契约文档提交到 main，通知重建轨道按同一契约实现

**验收**：`pnpm dev` 在 mock 模式下能跑通全部页面，不依赖任何后端服务。

## Task F1：设计方向 ✅ 已完成（2026-07-18）

产出：**[`docs/frontend/product-and-design-brief.md`](../../frontend/product-and-design-brief.md)**，经四轮产品访谈（16 问）与用户确认。

开工前必读该简报。其中直接改变本计划范围的三条：

1. **网站是两层结构**：产品官网首页 → "开始使用" → 应用本体。**首页是新增的一等交付物**，原 F0–F6 未包含，见下方新增的 F3.5。
2. **应用采用 Claude Artifacts 式双栏**：左对话 + 右作品面板（作品图 + 五维会诊 + 版本对照）。
3. **界面必须为作品让路**：右侧常驻学生彩色作品，界面近乎中性、强调色极少量——此约束高于任何审美偏好。

## Task F3：学生端主路径（**演示核心，优先级最高**）

> **2026-07-21 更新（用户定）**：对话界面改由 assistant-ui 基座（`/assistant-lab`）承接，**本任务中自建"对话主界面"的部分作废**；作品上传、五维会诊展示等改为在 assistant-ui 基座上实现。接入计划见 `2026-07-21-assistant-ui-own-backend-persistence.md`。

评委最先试、也最常试的路径。按演示顺序建：

- [ ] **入口页**：班级邀请码 + 匿名编号，零讲解可进入
- [ ] **对话主界面**：流式回复（后端已实现）、工具调用透明展示、消息历史。这是 Lumi 的门面
- [ ] **作品上传**：拖拽/点击上传、预览、上传进度（跨太平洋上传较慢，**必须有明确进度反馈**，否则会被当成卡死）
- [ ] **五维会诊展示**：五维总览 + 深谈 1–2 维 + **收束固定呈现**。收束在视觉上要与五维明确区分，不能做成第六张卡片
- [ ] **成长档案**：学习轨迹，只对本人可见，不做排名

**验收**：新用户不经口头解释可以完成"进入 → 提问 → 传作品 → 看会诊"的完整路径。

## Task F3.5：产品官网首页（访谈后新增，**评委的第一印象**）

- [ ] 首屏：一句话说清 Lumi 是什么 + "开始使用"主按钮
- [ ] **可交互演示**：写死剧本、不连真后端的小演示，让访客亲眼看到一段五维会诊怎么发生。⚠️ 必须明确标注为演示
- [ ] 能力区块：只讲产品不分身份，但**文案用场景化写法**，让学生与教师各自对号入座
- [ ] 入口分流：「以演示学生身份试用」（零门槛）+「我有班级码」（真实学生）
- [ ] 页脚：联系方式/预约演示。**不做定价区**
- [ ] 首页可用宋体标题（应用内仍用黑体），承担文化厚度

**验收**：一个完全不了解项目的人，看完首页能说出 Lumi 是干什么的、对谁有用，并知道下一步点哪。

## 纪律

1. 不越文件所有权边界；需要后端改动时提契约变更请求，不自己动手
2. 术语一律用 `CONTEXT.md`；界面文案不出现"通感阶梯""门禁""关卡"等旧词
3. **不做假数据充门面**：后端未交付的功能，页面不上线，不用 mock 数据冒充真实能力（参赛要求红线）
4. 遇设计取舍无法自决，写 `> DECISION NEEDED:` 停下等用户确认
