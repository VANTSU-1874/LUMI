本表在每次公开部署、演示数据重置、二维码更新和正式提交前各执行一次。每一项必须由实际操作人填写日期时间、设备/网络、结果和签名；“预计通过”“开发机通过”不能替代公网实测。失败项修复后新增一行复测记录，不覆盖原失败记录。

结果只允许：`通过`、`失败`、`不适用（说明原因）`。当前 `PUBLIC_APP_URL` 未确认、`public/competition-qr.svg` 未生成时，二维码项必须记录为失败/待完成，不能先签通过。

## 1. HTTPS 页面与证书

1. 用比赛现场计划使用的电脑和非校园网络手机分别打开新公网地址。
2. 确认 HTTP 自动跳转 HTTPS，地址栏无证书警告，首页标题为“触映”。
3. 打开 `/privacy`，确认隐私说明可达。
4. 开发者工具确认没有从旧项目域名加载脚本、图片或接口。

通过标准：两种网络均在 10 秒内加载，证书域名/有效期正确，无混合内容和旧项目依赖。

## 2. 学生演示入口

1. 在受控维护环境执行 `pnpm db:seed`，从终端当次输出获取班级码与四个演示匿名编号；不要从文档抄固定码。
2. 使用一个尚未进入过的演示编号，从首页选择学生入口并登录。
3. 确认工作台显示“演示数据”与“仅供竞赛演示，不代表真实学生成效”。
4. 记录使用的是 A/B/C/D 哪一演示档案，不在表内记录完整匿名编号。

通过标准：进入正确档案，真实/演示边界可见，刷新后会话与阶段恢复正常。

## 3. 六元逻辑作为开放学习支架

1. 使用新的演示档案进入六元交互逻辑，故意保留一项模糊或暂缺。
2. 直接询问创意、专业术语或工具步骤，确认导师先回答当前问题，不要求先补齐表单。
3. 确认导师把缺失关系作为后续建议说明，并允许学生继续查看课程资料、比较工具路径或做最小验证。
4. 通过自然对话逐步补充文化意图、参与动作、输入信号、映射规则、输出媒介和体验反馈，确认内容可保存并继续修改。

通过标准：六元逻辑帮助学生组织方案但不阻断答疑和探索；无模型时只标记待确认，不自动提交、评分或宣称阶段通过。

## 4. 真实截图净化与私有上传

1. 从真实课程过程截图复制一个测试副本，不使用比赛预置假截图。
2. 裁掉与信号证据无关区域；遮蔽姓名、人脸、手机号、邮箱、学号、聊天头像/通知、文件路径和设备序列号。
3. 由第二人复核净化结果，只保留证明输入/映射/传输/绑定/输出所需区域。
4. 以 5 MB 以下 PNG、JPEG 或 WebP 上传，填写层级、标签和探针；记录证据 ID，不把图片贴进本表。
5. 尝试直接访问文件静态路径，确认不可公开读取；从授权界面确认可查看。

通过标准：净化复核已签名；文件类型与大小受限；证据只经授权接口访问；界面不显示服务器文件路径。

## 5. 无模型确定性降级

1. 在维护窗口停止服务，移除全部 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 后重启；不能只移除其中一项。
2. 确认学生与教师工作台显示“确定性降级”。
3. 提交一张逻辑卡，确认本地规则、本地知识、证据与排障仍可运行。
4. 确认语义审查为待处理，不自动判定通过。
5. 记录测试后是否恢复了已批准模型配置；不要记录任何模型密钥。

通过标准：模型完全不可用时主流程可解释地降级，已输入卡片与证据不丢失，不出现虚假 AI 结论。

## 6. 教师端演示数据标签与统计隔离

1. 用部署时私下配置的 `TEACHER_ACCESS_CODE` 登录，不在本表记录值。
2. 默认打开班级分析，确认演示学习者不计入真实统计。
3. 显式开启“包含演示数据”，确认每个演示学生、项目、证据、排障和迁移记录都带“演示数据”标签。
4. 关闭开关，确认真实/演示数量再次分离，不出现混算。

通过标准：默认排除，显式包含后仍分栏/标记，不把演示结果写成真实教学成效。

## 7. 隐私删除与 tombstone 恢复

1. 学生删除自己刚上传的测试证据，确认列表立即不可见。
2. 由授权教师删除一条所管班级测试证据，确认审计只记操作身份/类型，不记内容或路径。
3. 在维护窗口执行 `pnpm evidence:recover`，确认返回成功。
4. 检查私有目录没有该证据的悬挂文件；不要手工删除 `.deleting-*` tombstone。

通过标准：数据库记录和私有文件一致删除；恢复命令幂等成功；其他项目证据不受影响。

## 8. `/api/health` 正常与脱敏

```powershell
$PublicBaseUrl = "https://<confirmed-public-host>"
$Response = Invoke-WebRequest "$PublicBaseUrl/api/health" -UseBasicParsing
$Response.StatusCode
$Response.Headers["Cache-Control"]
$Response.Content
```

通过标准：HTTP 200、`Cache-Control: no-store`、`status=ok`、数据库可用、通用设计、数字交互和书籍设计三个知识包均大于 0、`aiConfigured=true`、`agentQuality.status=passed`、`agentHarness.status=passed` 且 `competitionReady=true`；响应不含数据库/证据路径、密钥、班级码、匿名编号、教师码、学生信息或证据内容。另在受控演练环境使知识查询失败，确认稳定返回 HTTP 503 `degraded`，然后恢复，不在公网破坏生产库。

## 9. 二维码由两台设备跨网络扫描

1. 项目负责人书面确认新 `PUBLIC_APP_URL` 后，将它配置在安全环境；地址必须是公网 HTTPS，且不含登录凭据、查询参数或片段。
2. 执行：

```powershell
pnpm qr:generate
Get-FileHash public/competition-qr.svg -Algorithm SHA256
```

3. 在比赛展示页面/材料中使用生成的 SVG，不截图重绘。
4. 设备一使用校园 Wi-Fi 扫描；设备二使用蜂窝网络扫描。两台设备均核对最终 HTTPS 地址、证书和首页标题。
5. 再运行一次生成命令，确认 SHA-256 不变；把 hash 填入本轮信息。

通过标准：两台设备、两种网络都到达同一已确认新地址，无重定向到旧项目，无证书警告；重复生成 hash 一致。任何一台失败都不能签署比赛发布通过。

## 10. Agent 三知识包与受控行动

1. 通用设计学生输入“我想做一张酷一点的海报，但不知道先从哪里开始”，确认导师可直接回应并引用通用设计来源，不要求先填写课程表单。
2. 数字交互学生输入“声音已经有数值，但画面为什么还是不动？”，确认回答进入排障情境、引用数字交互来源并提出排障行动卡。
3. 不确认行动，验证页面不跳转、项目阶段不改变；再由学生确认，验证进入对应工作空间。
4. 书籍设计学生输入“给新生做校园社区活动导览册，信息为什么不能平均分？”，确认引用书籍设计来源，不出现 TouchDesigner 节点建议。
5. 完成书籍设计草稿保存、刷新恢复、社区居民受众迁移和版面证据提交。
6. 教师端分别查看通用设计、数字交互和书籍设计三个知识包的原问题、来源、行动状态和教师复核入口。

通过标准：通用设计和两门增强课程使用同一服务端 Agent 会话/策略/行动/复核链；知识来源不串包；未确认行动绝不执行；刷新后会话、行动和证据可恢复。

## 11. 匿名真实试用报告

1. 教师登录后选择本轮真实试用班级，点击“导出真实试用报告”。
2. 打开 Markdown 文件，确认数据边界为 `REAL_ONLY`，演示账号不计入人数、项目、Agent 回合、证据或教师复核。
3. 搜索学生匿名编号、别名、问题原文、证据原文和教师备注，确认均未出现在报告中。
4. 确认“任务是否真实完成、首次下一步、认知参与、主观体验”四项仍显示“待人工观察”。
5. 将 [真实试用匿名观察表](../templates/pilot-observation-sheet.md) 的人工记录与系统汇总并列归档，不覆盖原始系统记录。

通过标准：报告只给出可验证聚合行为，不暴露学习者级内容，不把系统日志推断为理解或教学成效；人工观察未完成时明确不允许下完整成效结论。

## 12. 教师真人 10 分钟演练

1. 使用比赛现场计划使用的电脑、浏览器和网络，按 [竞赛演示脚本](../competition-demo-script.md) 从首页开始计时。
2. 教师不看逐字稿，实际完成数字交互提问、行动确认、证据/排障、教师复核、书籍设计迁移、安全边界和收束。
3. 第二人在 0:45、5:10、7:50、8:45、9:30 和结束时记录实际时间及卡顿点。
4. 超过 10:00 或漏掉“来源、行动确认、教师复核、第二课程包、真实性边界”任一项，均记录失败；调整后重新完整演练，不覆盖失败记录。

通过标准：真人独立完成且总时长不超过 10:00，五个核心证明点均出现，执行人和复核人签名齐全。

## 13. 真实学生试用与双人复核

1. 按 [真实试用协议](../pilot-protocol.md) 邀请首轮 5—8 名数字交互学生，每人 20—30 分钟；书籍设计 3—5 名学生单独报告。
2. 先运行 `pnpm pilot:prepare` 创建本轮专用真实试用班；不得选择含既往教学记录的长期班级导出本轮报告。
3. 设置本轮班名、人数和实际公网地址后运行 `pnpm pilot:preflight`；只有8项检查全部通过才能发放编号。
4. 每名学生开始前，教师先填 [真实试用匿名观察表](../templates/pilot-observation-sheet.md) 的“可接受首次下一步与依据”。
5. 学生本人完成提问、行动确认和证据提交；教师不得代点、代答或代交。
6. 试用后教师在系统中复核 Agent/证据/迁移原判断，再补齐观察表；第二位教师抽查所有纠正与争议样本。
7. 导出真实试用报告，只用“本轮试用中观察到”描述小样本结果。

通过标准：首轮样本达到约定人数，所有纳入样本均为 `REAL` 且有完整匿名观察表；停止条件未触发或已排除相关样本；教师与第二复核人记录可追溯；不使用“显著提升”“普遍有效”等无依据结论。
