# Lumi 鹿鸣：产品与设计简报

> 来源：2026-07-18 与用户的四轮产品访谈（16 个问题）。本文是前端重写轨道 F1 的交付物，也是 Task F2 设计系统的依据。
> 术语以 `CONTEXT.md` 为准；产品定义以 `docs/superpowers/specs/2026-07-18-lumi-design-tutor-design.md` 为准。

## 一、产品定位

| 项 | 结论 |
| --- | --- |
| **产品名** | **Lumi 鹿鸣**。"触映 / 触映AI"是旧名，**已废弃**，界面与文案中不得出现 |
| **目标用户** | 视觉传达设计专业**高职专科学生**（初学→进阶→提升全程）+ **任课教师** |
| **体验优先级** | **学生优先**。三类人体验冲突时，先保学生长期好用；评委的理解成本由**官网首页**承担 |
| **商业定位** | **真想做成产品**，不止参赛。但当前阶段**不做定价**，首页只留"联系我们/预约演示"入口 |
| **域名** | `lumi.bot.cd`（S0 正式入口） |

### 用户应该相信什么

**"它比通用 AI 更懂这个专业，也更懂我这个学生。"**

支撑这句话的四件事：课程化专业语料（带来源）、成长档案（跨会话记得你）、双面孔（该讲道理时讲道理，该排故障时排故障）、导师品格（不直接代做）。

## 二、网站两层结构

```
lumi.bot.cd  →  产品官网首页（介绍 Lumi，像真产品）
                     └─ [开始使用] ─┬─ 以演示学生身份试用（零门槛，给评委与访客）
                                    └─ 我有班级码（真实学生）
                                         ↓
                                    应用本体（ChatGPT / Claude 式）
```

### 首页

- **只讲产品，不分身份区块**（像 ChatGPT 官网），但⚠️ **文案要兼顾多种身份**：每讲一个能力都要用场景化写法，让学生和教师各自对号入座。例：不写"支持知识库检索"，写"问'这个网格为什么不对'，它会指着你的版面说话，并告诉你依据来自哪份课程资料"。
- **核心展示物：可交互演示**（写死剧本，不连真后端）。访客能亲眼看到一段会诊怎么发生。理由：产品尚未定型，截图会变；且演示比截图有说服力。
- **不做定价区**；转化入口是"开始使用"与"联系我们"。

### 应用本体

- **整体壳**照搬 ChatGPT / Claude 的成熟范式，零学习成本。
- **左侧边栏**：顶部课程切换，下面是**按课程分组的历史对话** + 成长档案入口。学生的心智模型就是按课分的。
- **顶部课程切换器**：当前课程一目了然、随时可改（像 ChatGPT 选模型）。学生要能知道 Lumi 此刻在用哪门课的知识回答。
- **右侧作品面板**（Claude Artifacts 式）：常驻显示学生作品图 + 五维会诊，左侧继续对话追问。
  - ⚠️ **与 Claude 的关键区别**：这里的 artifact 是**学生自己的作品**，不是 AI 生成物。因此面板需要的是**缩放、局部圈注、版本对照**，而不是复制/下载。
  - **版本对照**是白捡的高价值功能：成长档案里有历史版本，面板可并排"上一版 vs 这一版"——这正是收束那句"相较上次"最有说服力的呈现。
- **收束的呈现**：五维之外单独一块，视觉上必须与五维明确区分，**不得渲染成第六张并列卡片**。

## 三、视觉方向

**气质关键词：克制、专业、有文化厚度、不炫技。**参照专业设计画册与展览手册的排版感，而非 SaaS 模板。

### 铁律：界面必须为作品让路

右侧面板永远显示学生的彩色作品。**界面用色一旦过重，就会干扰学生对自己作品色彩的判断**——这是 Figma、Photoshop 界面都是中性灰的原因。

因此：**界面近乎中性，强调色极少量使用**（仅用于关键操作与状态）。这条约束高于任何审美偏好。

### 配色

- 底色：暖白（不用纯白，避免与作品白底混淆），深色文字用墨色而非纯黑
- 中性灰阶：至少 5 级，用于分隔、次要文字、禁用态
- 强调色：**一个**即可，取"光"的意象（暖金/琥珀方向），仅用于主操作与当前态
- 语义色：成功/警告/错误各一，低饱和，不抢眼

> **首页例外（2026-07-20 用户定）**：官网首页整页采用参考站（obsidianassembly.com）的暖褐/焦糖色系与颗粒纹理，取色令牌见 `homepage-copy.md` 首屏节。**应用本体不受影响**，仍守上述暖白与中性灰——作品让路铁律只会更严，不放松。

### 字体（中文是重点，设计专业评委一眼会看）

- **首页标题**：宋体（思源宋体等开源可商用字体）——文化厚度与设计感
- **应用内与正文**：黑体（思源黑体 / Noto Sans SC）——可读性与工具感
- 英文与数字：Inter 或系统字体栈
- **中文排版专项**：正文行高 1.75–1.8（中文比英文需要更大）；正文不加字距，标题可微调；中英混排自动加空格；标点挤压处理

### 密度

- 首页：舒展，大留白
- 应用内：紧凑，工具应有的信息密度

### 深色模式

**先只做浅色**，但设计令牌用 CSS 变量写，预留接口。
理由：作品图在深色背景下色彩判断会失真，对设计评图不利；且工作量翻倍。

### 品牌标志

做**一个克制的抽象标志**（鹿 / 光的几何化意象），用于首页、对话头像、二维码。不做拟人化吉祥物——与"专业克制"的方向冲突。

## 四、移动端

**完整可用，单栏降级。**二维码是比赛硬要求，评委很可能扫码用手机试——手机端体验差会直接毁掉第一印象。

- 双栏降级为单栏：对话为主，作品与会诊面板可上拉/切换
- 全流程可跑通：进入 → 提问 → 传作品 → 看五维会诊 → 看收束
- 手机拍作品直接上传要顺畅（学生的真实用法就是手机拍完就传）

## 五、对开发的直接约束

1. 界面文案不出现"通感阶梯""触映""门禁""关卡"等旧词（`CONTEXT.md` 纪律）
2. 收束不是第六维，前端渲染不得并列
3. 后端未交付的功能，页面不上线，**不用 mock 数据冒充真实能力**（参赛红线）
4. 首页可交互演示必须**明确标注为演示**，不得让访客误以为是实时真实数据
5. 作品图上传要有明确进度反馈——服务器在洛杉矶，跨太平洋上传较慢，没有进度条会被当成卡死

## 六、仍待确认

1. 标志的具体形态（需设计稿或用户指定方向）
2. 首页可交互演示用哪门课的哪个案例（建议用演示脚本主线：数字交互文创设计）
3. 是否换含 lumi 的域名（不阻塞）
