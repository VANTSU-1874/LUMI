# “触映”竞赛演示脚本

> **⚠️ 历史材料（已被 Lumi 当前材料取代）**：本文仅保留作历史记录，不代表当前产品能力或演示状态。现行演示与部署边界见 [Lumi 比赛演示脚本](runbooks/demo-script.md) 和 [Lumi S0 部署冒烟 Runbook](runbooks/deploy-s0.md)。

## 演示目标

在 10 分钟内证明“触映”是教育智能体，而不是课程资料网站：它读取课程包、学习状态和证据，判断学习情境，给出有来源的回答，提出待确认行动，并把学生操作与教师复核连成证据链。

演示数据统一使用 `%LOCALAPPDATA%\ChuyingAI\config\access-info.txt` 中的受控账号。不要在投屏、录屏或提交材料中展示教师码、完整匿名编号、Cookie 或模型密钥。

## 开场结论（0:00—0:45）

> 触映是面向高职设计类项目制课程的认知诊断与迁移学习智能体，以数字交互文创课程作为首个深度应用场景。它不是替学生完成作品，而是在学习前诊断、学习中排障、学习后迁移，并把每次建议的依据、行动和结果留给教师复核。

屏幕动作：打开“学习对话”，指出回答区、课程状态和输入框。不要先从案例库开始。

## 场景一：数字交互排障闭环（0:45—5:10）

### 1. 学生提出真实问题

输入：`声音已经有数值，但画面为什么还是不动？`

必须展示：

- Agent 判断为排障情境，而不是泛化讲概念；
- 直接答案先出现；
- 展开后能看到课程来源、为什么建议这一步和不确定性；
- 行动卡在学生确认前不跳转、不修改项目。

### 2. 学生确认行动

确认“开始排障”或对应工具行动，进入节点/排障工作区。说明模型只提出白名单行动，服务端仍检查学生归属、有效期和幂等性。

### 3. 用证据而不是猜测推进

展示输入、映射、传输、绑定、输出五层中的当前层；提交或打开一条数值/结构证据。指出 Agent 会读取当前项目阶段、画像、工具状态和证据数量，但不会替学生自动通过门禁。

### 4. 教师复核

切到教师端，打开该学习者的“智能体判断时间线”，展示原问题、原回答、建议原因、来源标题、行动状态和教师追加复核。强调教师纠正不会覆盖原判断。

## 场景二：书籍设计迁移微闭环（5:10—7:50）

### 1. 证明课程包可替换

回到学生端，在对话中提出：`给新生做校园社区活动导览册，信息为什么不能平均分？`

展示 Agent 使用书籍设计来源回答，而不是调用 TouchDesigner 节点；再确认打开“8页导览册编排台”。

### 2. 完成最小学习闭环

依次展示：

1. 三个快速诊断，识别学生是从受众、任务还是装饰开始判断；
2. 八页信息层级与阅读路径；
3. 保存草稿并刷新恢复；
4. 将受众从新生切换为社区居民；
5. 确认“改变入口、改变行动召唤、保留活动核心”；
6. 提交版面证据并得到 4 项量规结果。

切到教师端，展示“书籍设计微闭环”证据。结论是同一 Agent 内核、同一会话/来源/行动/画像协议进入第二门课程，不是又做了一个孤立网页。

## 安全与降级（7:50—8:45）

展示或口述：

- 仅在模型超时、限流、传输失败或服务宕机时进入确定性降级；可选 sidecar/JSON 解析失败和没有课程来源都不打回导师正文，后者按通用设计建议作答并标明不确定性；
- 降级不自动通过教学门禁；
- 未覆盖的装帧、材料或印刷工艺会明确资料边界或转教师；
- 客户端不能伪造行动内容，行动必须来自已保存回合并由学生确认。

## 数据与成效边界（8:45—9:30）

教师端默认排除演示数据，勾选后才显示。指出“导出真实试用报告”只汇总 `REAL` 数据，且首次下一步、认知参与和主观反馈仍要求教师现场填写。明确说明：只有当 37 题 V3 结构评测、40 题真实模型质量门和 8 项真人体感门全部通过后，才能把这些结果作为竞赛证据；在真实 40 题和 8 项真人验证完成前，不得宣称质量门已通过，也不宣称“显著提升成绩”或“已证明课堂提质”。

## 收束（9:30—10:00）

> 触映的通用部分是认知诊断、情境路由、知识检索、行动确认、学习证据与教师复核；课程差异被封装在课程包和工具适配器中。数字交互证明深度，书籍设计证明迁移，真实课堂试用将继续验证效果。

## 演示前门禁

- `pnpm agent:eval`：V3 专业路由、来源账本和权限结构评测通过；
- `pnpm tutor:quality`：40 题真实模型质量门通过；
- `pnpm agent:harness`：16类正常、异常、越权、幂等与迁移场景全部通过；
- `pnpm local-host:prepare`：备份、迁移和三个知识包导入通过；
- `pnpm build`：生产构建通过；
- `pnpm local-host:start` 后运行 `pnpm local-host:verify`：`agentQuality.status=passed`、`agentHarness.status=passed` 且 `competitionReady=true`；
- 手机和电脑各完成一次登录、对话、行动确认与依据展开；
- 演示人员完成一次不看稿计时，保留实际时长和卡顿点。
- 教师端“导出真实试用报告”可下载，报告不含学生级原文，四项现场指标保持待人工观察。
