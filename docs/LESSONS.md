# LESSONS —— 三方共享经验教训本

> 谁读:每次任务开工前,Claude 和 Codex 都先读这里。
> 谁写:执行前复核发现计划缺口、或踩到不显而易见的坑时,追加一条。
> 规则:
> - 一条一句,`- YYYY-MM-DD ` 开头;
> - 追加前先扫一遍,已有类似的就补充、不重复;
> - 只记**跨任务能复用**的教训,不记"我完成了X"这类流水账;
> - **抽象化**。此文件进 git、团队可见,禁止写生产 IP / 密码 / 密钥 / 绝对备份路径等敏感信息。

- 2026-08-11 动态/交互作品的作品形态必须与采集到的证据媒介分开建模；静态封面只能作为降级预览，不能证明运动、交互、声音或实时行为，行为声明须绑定动态媒体或来源陈述并标注证据覆盖程度。
- 2026-08-12 原始候选元数据只能作为治理材料；只有受控图组、作品—原始来源匹配、来源角色、权利证据、规范化分类、视觉描述、重复关系及策展/教学建议全部由严格合同绑定后，才可计入教师审核队列。
- 2026-08-12 权利证据门表示使用边界已经查明，不表示获得正式发布授权；站点分享条款与作品页作者版权并存时，可把未改动素材限制在教师私有复核，并把再发布决定继续保持 `UNKNOWN`。
- 2026-08-12 网络资产包通过摘要、解码和索引校验后仍不能直接成为受控图组；派生 ReviewPack 前必须隔离站内广告、低分辨率变体与跨作品共享情境图，并保持原始交付包不可变。
- 2026-08-12 来源角色必须按具体页面及其署名事实判定，不能按整个域名硬编码；同一站点可能同时承载官方作品页与策展记录。
- 2026-08-12 图片放大器的导航控件应与可滚动、可裁剪的媒体舞台分层；仅提高 `z-index` 仍可能让移动端原生指针事件落到画布而非按钮。
- 2026-08-12 大批量 ReviewPack 应让机械构建器从不可变索引补候选 ID、尺寸、哈希、预览路径和关闭边界，但来源、权利、视觉、策展与教学语义仍须逐项审计，不能由模板自动升格。
- 2026-08-12 审核队列汇报必须区分累计严格 ReviewPack、当前待教师审核与已进入私有 WikiDraft 的数量，并在每批导入后从数据库重读状态，不能沿用先前快照。
- 2026-08-12 产品允许缺证素材先交人工判断时，应新增显式的证据缺口审核对象与状态，逐门保留 `MISSING/UNVERIFIED`，不能放宽严格合同或把人工接受缺口反写成九项齐备；后续正式发布仍需独立门禁。
- 2026-08-12 公开图片的响应 MIME 与实际字节格式冲突时，不能把可用素材直接归类为“无图”；应在受控来源与安全重定向边界内，以文件魔数、真实解码、尺寸和哈希联合验真，并把响应头异常保留为审计事实。
- 2026-08-13 受控发布从试点包升级为完整包时，特权包装器的 bundle 路径、应用层 bundle identity 和 Release 内只读存在性检查必须作为同一合同同步升级；否则正确的身份校验会在切换阶段拒绝新包。
- 2026-08-12 对退回、拒绝等需要理由的教师动作，不要用无说明的禁用按钮隐藏前置条件；应允许点击后就地说明必填原因并把焦点移到对应字段，同时让服务端继续执行同一硬校验。
- 2026-08-12 已审核结论需要再次编辑时，应以当前审核 revision 做并发校验并追加一条新决定，预填上次判断且保留原审计记录；不能原地覆盖第一次决定，也不能因此打开发布或学生能力。
- 2026-08-12 教师界面的证据材料应通过独立本地化显示层提供中文，保留原始标题、署名、URL、证据正文与 material hash；不得为了汉化直接改写不可变 ReviewPack。
- 2026-08-12 产品明确允许教师对未知来源、角色与权利先行判断时，`UNKNOWN` 必须是独立的已确认事实状态，不再进入草稿动作的缺口勾选或必填说明；退回和拒绝仍须记录理由，发布门禁继续关闭。
- 2026-08-12 艺术表现风格不能用作品类别或普通画面描述代替；应使用受控词表标注风格取向，并另存与可见图像绑定的判断依据。
- 2026-08-12 审核动作中的 `PRIVATE_WIKIDRAFT` 只是候选状态，不能冒充已经存在的可编辑草稿实体；编纂层必须独立保存可编辑物料、来源决定绑定、revision/hash 与追加式编辑历史，并继续与 canonical Page/Revision/Compiled Truth 分层。
- 2026-08-12 同一产品的教师端与学生端需要配色一致时，应把当前可见工作台色板提升为共享语义 token 并让两端共同引用，不能复制一组“近似色”后各自演化；危险等语义色仍须独立保留。
- 2026-08-13 可编辑私有草稿的教师四域预复核必须与正式 canonical 角色治理分表、分合同；前者可追加修订并确认未知权利的私有边界，但不能生成正式角色决定、内部目录或发布资格。
- 2026-08-13 当现有 canonical S1 权利合同无法表达 `UNKNOWN_PRIVATE_ONLY` 时，内部目录准入必须走加法式私有治理合同：绑定真实教师、显式域角色、当前人工决定和精确 Page/Truth 哈希，禁止把未知改写为 `ALLOW` 或用伪造多人身份补齐职责分离。
- 2026-08-13 跨阶段合同绑定上游哈希时必须复用上游的精确编码规则，不能因新层自己的审计哈希带 `sha256:` 前缀就给被引用的 64 位内容摘要补前缀；隔离数据库应同时验证格式和真实阶段衔接。
- 2026-08-13 当一批私有预复核只需人工判断一个领域时，其他领域应根据教师的明确批量确认生成逐项追加决定，界面再聚焦目标域批量分流；不能仅隐藏未判断字段或把私有批量确认冒充正式分域治理。
- 2026-08-13 当内部目录已完成但正式发布仍受权利或范围授权阻断时，下一步应先生成逐项只读发布准备审计并保持通道关闭；不能把“继续执行”或私有准入自动解释为学生可见授权。
- 2026-08-13 用户授权继续推进发布流程只能满足操作范围与发布角色签核，不能替代逐作品的学生展示权利依据；正式 Release 必须同时绑定授权操作、作品权利和可撤回通道状态。
- 2026-08-13 将设计完成的浏览页接入真实 API 时，加载、错误和零结果必须留在同一页面框架内，不能提前返回成另一套简化页面；嵌入既有工作台时还须明确唯一导航归属，避免外壳与内页重复顶栏。
- 2026-08-13 登录服务位于已校验来源的同机反向代理后时，认证库必须同时登记公网来源和代理实际重写出的精确内部来源，并用真实代理头回归登录请求；只验证入口代理或只配置公网域名都会造成生产同源请求被二次误拒绝。
- 2026-08-13 将试点发布扩展为全量发布时，资格、Canonical 与生产包必须按候选身份同时承载严格审核轨和显式缺证轨，不能用严格包计数或路径断言把已由教师接受的缺证案例伪装成严格案例或静默遗漏。
- 2026-08-16 为已发布内容追加站内检索能力时，应使用独立的内容寻址索引和发布切换绑定，并在查询时与当前有效页面求交集；不能改写历史 Release 的关闭字段，也不能把站内图文检索自动扩大为外部向量服务、对象存储或回答链引用。
- 2026-08-17 登录后内容的检索索引即使不含原图，也可能重现标题、来源与内部标识；公开代码仓只提交实现与无明细摘要，完整索引必须作为签名构建包的受控侧车原子发布。

## SQLite / 数据备份
- 2026-08-08 R2 私有材料上传前必须分别关闭 `r2.dev` 与所有自定义域名的公共访问并回读验证；控制台仅限本人管理、桶根目录不可列举或自定义域名受保护，都不能证明另一条对象 URL 入口是私有的。
- 2026-08-07 K12 回退控制对象的 parser/content version 必须与其控制 corpus 完全一致，并在创建隔离活动指针前由封装器重放校验；升级 generation 版本时不能只改 bundle 外壳。
- 2026-08-02 生产候选迁移不能只从候选 schema 生成最后一条 SQL；打包前必须将线上 release 的 `__drizzle_migrations` 时间戳/哈希与候选 journal 逐序绑定，并把生产末项新增的 schema 对象保留在候选 schema/snapshot 中，新迁移只能在其后追加，否则生成器可能误判重命名而安全迁移器应以 `MIGRATION_HISTORY_GAP` 拒绝。
- 2026-07-22 只读打开 WAL 模式库(`?mode=ro`)仍会在库所在目录生成 `-wal/-shm`,污染快照目标目录;读备份/restore point 一律先 `cp` 出副本、再用 `?immutable=1` 打开,绝不就地打开。
- 2026-07-22 备份/restore point 创建并验证后要物理封存(`chmod a-w` + `chattr +i`),否则任何后续读取都可能往里加文件、破坏文件集不变量;清理封存目录前必须先 `chattr -i`,否则连 root 都删不掉。
- 2026-07-22 判断"备份主库是否被改坏"用「现算 sha256 == manifest 登记值」为硬门槛,再用备份目录**之外**的 verified marker 做外部锚点;别假设某个 result 文件里有你需要的字段。
- 2026-07-22 更稳的做法是让备份产物天生就不是 WAL 模式(`VACUUM INTO`,或 checkpoint 后 `journal_mode=DELETE`),从源头免掉旁生文件问题,连 `immutable` 都不用操心。
- 2026-07-26 备份包装器与发布器必须共享同一套封存权限契约;若一方把恢复点设为更严格的目录模式和不可变位、另一方却只接受固定模式,后续备份会在已创建并验证新恢复点后仍持续误报失败。
- 2026-07-28 SQLite 表重建迁移必须逐项复核旧表复制列、生成列和手写触发器是否被正确保留,测试夹具也应始终显式列出插入列,避免加列后位置式 `INSERT ... VALUES` 全面失效。
- 2026-07-28 跨分支移植数据库变更时必须以目标稳定线的迁移 journal 与 snapshot 为准重新生成下一号迁移，再补回生成器不承载的手写触发器；不能沿用实验分支的迁移号覆盖目标历史。

## 脚本 / 校验
- 2026-08-09 清理旧生产 release 前必须由特权只读盘点确认完整发布标记、成功切换证据、实时进程/符号链接零引用，并至少保留 current 与最近两个已验证前置版本；删除前后都要重验完整健康，且不得联动清理数据库恢复点、审计证据或模型索引。
- 2026-08-09 模型质量与 harness 报告均已完整通过、但审计包装器在密封前失败时，受控恢复只能接受同一候选提交、精确失败证据、未改生产状态与仍在新鲜窗口的原报告；不应为修补控制面元数据而重跑外部模型。
- 2026-08-09 受控发布上传前必须按“用户输入包+根级验真副本+展开后 release+恢复点”计算峰值空间；仅在根级副本已完成签名、哈希和归档验真后才可消费可恢复的上传副本，并只清理同失败提交及失败证据绑定、且未密封的暂存目录，否则单看发布包大小会在准备中途写满磁盘。
- 2026-08-09 生产切换的一次性确认令牌不得打印到标准输出或作为进程参数传递；应存于 root-only 密封文件，由受控包装器在内部验哈希后消费并删除。
- 2026-08-08 Linux 发布子进程即使已经 `source` 服务配置也必须显式传递服务配置选择器，不能让 `SERVICE_REQUIRED` 回退依赖 Windows 的 `LOCALAPPDATA`；首次加载大型本地模型的健康等待还应使用有限但覆盖冷启动与回退启动的窗口。
- 2026-08-08 Windows 上按原始字节封存的嵌套评测 generation 必须用递归 `.gitattributes` 明确 `eol=lf`；父目录的 `*.json` 规则不覆盖子目录，语义与 Git blob 均未变时也会因工作区 CRLF 让 manifest 哈希门失败。
- 2026-08-08 受控发布器应把准备阶段的服务/数据库/模型基础健康与切换完成后的 `competitionReady` 质量硬门分开；旧报告过期可以阻止切换，但不能阻止创建恢复点和验真不可变候选，否则无法在生产不变的前提下修复质量门。
- 2026-08-07 批处理验证器不能只把 PASS 报告打印到标准输出；正式阶段必须原子持久化同一份验证工件并让后续提交与门禁只读绑定该文件，否则控制台成功会与版本化审计状态漂移。
- 2026-08-07 批量 K10 面对历史 K9 多种 JSON 形态时必须先统一成来源哈希、对象、Evidence、页锚、权重和治理标记的 canonical envelope，再由唯一写入者合并 generation；旧严格运行时若强制默认 action，条件性对象应留在引用侧车而不能伪装成默认行动。
- 2026-08-07 将哈希绑定的外部原始解析闭包提交到 Windows Git 工作树前，必须用目录级 `.gitattributes` 把原始 Markdown、JSON、图片和归档统一设为 `-text` 并在暂存后比对 blob 与工作区哈希，否则自动行尾转换会让未来检出无法复现原始闭包。
- 2026-08-04 外部解析结果包中的 `_origin.pdf` 可能与上传源文件页数相同但字节不同；审计必须分别冻结准入源 SHA 与服务返回副本 SHA/页数，不能把前者直接套作后者的完整性声明。
- 2026-08-04 外部异步解析的 `pending`/`running` 是正常队列状态；提交成功后必须在当前运行内只持有同一任务的最小句柄并做有限长、带退避的轮询，网络失败未取得可恢复句柄时只能记远端状态未知并禁止盲重传，任务结束后不持久化凭据、签名链接、正文或可复用下载信息。
- 2026-08-04 正式来源批处理不能仅凭文件名或旧盘点结论入队；必须在当前窗口重放文件存在性、字节、SHA-256、物理页范围与版本/样章身份，并把核验事实、处理授权和贯穿下游的治理标记分开；身份冲突只有在明确授权且禁止猜测时才可带标记继续，物理范围不明仍须隔离。
- 2026-08-04 外部解析接口按页数限制分段时，必须先在本地物理拆出精确页段再分别上传；不能用服务端页码参数配合同一整本原件重复上传，否则会把未授权或非目标页一并发送。
- 2026-08-04 外部 MCP 的官方文档字段可能滞后于当前包；修复配置时必须以锁定版本的本机 CLI schema 与模型枚举交叉验证环境变量名、模型值和服务地址，不能把旧版通用 `SERVER_URL` 字段直接套到新版专用 provider 字段。
- 2026-08-04 历史 OCR 工件只能证明某条受控路线曾产出结果，不能证明新执行窗口已把相同 MCP 加载为可调用能力；批量 fail-closed 审计必须把备用运行时缺失与路线永久不可用分开记录，并在恢复前同时核对配置、启动器和当前工具注册。
- 2026-07-29 从 Windows 用 `scp` 暂存 Linux 运维脚本后，必须在远端显式核对并收紧模式（安装器 0700、载荷 0600），再做非 root 入口试跑；不能把 Windows 权限映射当成 Linux 可执行位证据。
- 2026-07-29 用 `df` 与 `du` 对账时，非 root 的 `du` 会静默漏掉不可遍历的 root-owned release、备份和容器目录；必须先做有界的特权只读统计，再判断差额来源，不能把权限盲区误判为已删除但仍占用的文件。
- 2026-07-28 数据迁移前的“备份可用”不能只靠清单和完整性校验;还要在隔离目录实际恢复并用恢复库跑关键读链路,且创建、验证、恢复三步都应显式打印同一数据库来源。
- 2026-07-31 多配置环境的恢复演练不得运行会自动选择数据库来源的默认备份 CLI;应复用纯函数并显式绑定临时数据库、证据、备份和恢复目录,同时在结果中声明服务库和项目库均未使用。
- 2026-08-01 跨工作树生成的内容寻址运行时包不能只绑定 corpus、index 和模型哈希；manifest 还要记录来源提交，隔离验收结果再同时绑定 manifest 摘要与实际验真的 provider 集合，否则控制面元数据会被误读为已交付能力。
- 2026-08-01 Linux 虚拟环境的 `bin/python3` 通常是符号链接；sidecar 启动前应跟随链接并验证最终目标为普通文件，同时继续拒绝目录和失效链接，不能用 `lstat().isFile()` 把标准 venv 误判为非法运行时。
- 2026-08-01 生产灰度不能用“候选已发布、开关已开启、health 正常”代替知识运行时就绪；进入证据消费前必须从活库只读证明 schema、corpus、index 与活动指针存在，并确认发布物携带目标平台可加载的模型和 sidecar 工件，否则 shadow 可能只是无作用开关而下一阶段必然 unavailable。
- 2026-08-01 可复用回滚脚本的结果不能硬编码上一次事故原因；每次运行应显式绑定本次停止原因并分别记录切换前、候选和回滚后 release，否则回滚本身成功也会留下错误归因。

- 2026-07-25 发布预检不能只检查构建产物和依赖目录;systemd `ExecStart` 引用的源码入口也必须按服务账号实测可读,否则会在切换后才暴露 `ERR_MODULE_NOT_FOUND`。
- 2026-07-26 Composer 能力筛选与单轮外部工具授权是两条独立门禁;未显式选择能力时仍须保留已经确认的授权工具,显式选择后才按该能力白名单收窄,避免 UI 分类误伤原有安全授权链。
- 2026-07-26 生产模式浏览器 E2E 若直连应用而绕过受信代理,必须在每个用例开始动态签发代理来源头并覆盖登录与写操作,且登录后的鉴权断言要走浏览器内请求以保留 Secure 会话,不能复用过期静态签名或独立无会话请求上下文。
- 2026-07-26 构建脚本若会切入临时工作目录，必须在切换前把输入和输出路径规范为已校验的绝对路径；相对输出会被误写进临时目录并在 cleanup 时静默丢失。
- 2026-07-28 时间敏感或高成本测试的确定性参数（业务时钟与专属超时）必须按最坏完整套件场景显式注入，不能依赖系统当前时间或单文件耗时基线。
- 2026-07-28 E2E 必须从正式路由验证实际挂载的交付组件；只测未被正式入口引用的组件，即使单元与集成测试全绿也不能证明功能对用户可达。
- 2026-07-28 同一消息若会先独立持久化、再随运行创建做幂等复写，两条路径必须携带完全相同的结构化元数据；只对齐 ID 与正文仍会被正确判为内容冲突。
- 2026-07-27 `srcdoc` 产物的"零外部请求"不能只靠绝对 URL 正则;服务端应覆盖相对资源与导航等请求通道,并给文档注入 `default-src 'none'` 的 CSP,iframe 仍只给 `allow-scripts`。
- 2026-07-27 跨格式语料桥接不能只列字段对照;目标契约中的派生必填项、封闭枚举路由及下游穷尽映射、默认值来源和转换器拥有的产物边界都要固定下来,否则同一源文件无法稳定重算或通过类型门禁。
- 2026-07-27 目标字段名为 `localDocument` 时应保存可解析的源文件路径,不要把来源类别或材料名称伪装成路径;来源标签留在源条目或独立 provenance 字段中。
- 2026-07-27 语料格式桥接必须保留源格式中承载学生自然问法的检索锚点;若目标无独立 query 字段,应确定性并入可检索正文,否则 Schema 全绿也可能命中错误条目。
- 2026-07-27 按重复子标题切分长文档时,最后一个子块也必须显式止于下一个更高层级标题;把 EOF 当默认边界会把后续章节的全部图片和正文误吞进末条记录。
- 2026-07-27 扩充固定评测集不能只改题目 JSON;案例总数还会进入报告 Schema、比率分母、断点进度、阈值边界测试和验收文档,漏同步会让报告拒绝解析或静默算错。
- 2026-07-28 冻结“每课程包等额且语义全新”的评测契约前，必须先按 canonical 证据节点和既有 suite 做容量审计；小课程包若已被旧 DEV 覆盖大多数意图，应显式声明重叠控制或重配样本，不能靠重命名 family 凑独立性。
- 2026-07-28 一次性 DEV 评测在暴露结果前，必须把工单列出的每条回归/验收命令至少走到实际入口；参数解析成功不代表执行分支已接通，残留占位分支会让主结果暴露后才发现回归证据无法生成。
- 2026-07-28 检索证据的可复现 attestation 不能直接哈希含 `timingMs` 的 provider result；先投影到稳定的状态、命中、排名、分数与 identity 字段，否则相同证据会因运行耗时产生 unstable/cache-parity 假回归。
- 2026-07-27 跨多个 CLI 做数据摄取前后对比时,必须让每个命令显式选择并打印同一配置来源;命令名相邻不代表它们默认读取同一数据库。
- 2026-07-27 OpenAI-compatible Responses 供应端可能支持 `web_search` 却拒绝附加的 `max_tool_calls`;兼容重试应先保留 hosted tool、只去掉被明确拒绝的限制字段,不能把单个字段不兼容误判成联网能力整体不可用；若重试再出现约固定时长的 5xx，应结合供应端日志区分中转网关上限与本地超时，延长本地预算不能修复前者。
- 2026-07-27 报告回填工单引用的占位文案可能已随底稿迭代消失;只准备材料时也要先只读核对当前章节锚点,记录真实建议插入位置,不能假设旧字符串仍存在。

## 调研 / 第三方依赖
- 2026-07-27 内置 web 工具(WebFetch/WebSearch)依赖的后端小模型不可用时整条链路会一起失效;此时改用 `gh` API、浏览器工具或对方公开 API 直读同样能拿到材料,不要因为一个工具报错就判定"取不到"。
- 2026-07-27 第三方 skill/插件包可能缺失其自身 SKILL.md 引用的资源(脚本、manifest、参考图);评估可行性必须解包核对实际文件清单,不能只看描述与文档。
- 2026-07-27 registry 搜索接口未必匹配 identifier(如只匹配中文名与描述);直接用 identifier 搜到 0 条不等于条目不存在,应换关键词或换字段复核后再下结论。
- 2026-07-27 引入外部能力前先确认宿主生态是否对得上(目标 agent 的 skill 目录、运行时依赖);生态错配会让安装"成功"但完全不生效,这类问题不是安全问题而是可行性问题,应在计划阶段就查明。

## 部署 / 生产状态
- 2026-08-13 内含原始字节摘要的发布包必须为文本工件显式锁定 `eol=lf`、为媒体工件锁定 `-text`，并对真实 `git archive` 成员重算摘要；否则 Windows 导出过滤可在不改 Git blob 的情况下把 LF 改成 CRLF，导致生产导入器正确拒绝。
- 2026-07-22 线上状态值(如 `current` 指向哪个 release)一律以服务器现场 `readlink -f` 实测为准,不信脚本里硬编码的假设值——回滚失败后实际状态可能和脚本预期相反。
- 2026-07-24 发布构建若沿用 `umask 077`,会让 `.next`/`node_modules` 的目录和文件仅 root 可访问;切换前必须显式恢复服务账号所需的 group 读/执行权限,并按实际 `User/Group` 做候选 release 预检。
- 2026-07-22 自动回滚判断"备份能不能用"要基于封存哈希清单(旁生文件改不了主库哈希),别在回滚路径上跑会因自污染而中止的 in-place 校验,否则回滚会被自己造成的污染卡死。
- 2026-07-24 `git bundle verify` 需要一个现有 Git 仓库作为对象上下文,不能在 systemd 临时任务的无仓库工作目录里当作独立文件校验器;部署入口应先核对 bundle 的精确 ref/SHA,再让 `git clone` 完成 pack 完整性校验。
- 2026-07-22 高危流程的目标形态是:单次 sudo、同步等待、阶段状态机(每阶段落盘可续跑)、attempt 作用域证据(每次一个 runId,不覆盖、可幂等重试)、失败自动回滚;否则"异步提交→下轮查结果→失败起 r2"会退化成反复输密码的空转。
- 2026-07-27 免密发布权限绝不能直接指向用户可写脚本或任意服务器输入;必须由 root-owned 固定入口验证签名与哈希并把 prepare 和 cutover 分开,否则“少输密码”会变成普通账号可利用的服务或特权升级。
- 2026-07-28 受限发布的签名清单必须如实、成对声明迁移和环境变更，并把可执行值收窄到已审计的具体加法迁移与单一布尔键；不能为复用旧入口把实际迁移伪写成 `not-required`，也不能退回任意 root 脚本。

## 生产浏览器验收 / 诊断
- 2026-07-23 未命名会话首回合在主回合持久化后可能再触发独立的自动标题模型调用;主回合 `aiMode` 应以持久化消息与 runtime events 判定,页面总耗时和模型请求总数不得与预命名 smoke 严格对比。
- 2026-07-23 生产浏览器 smoke 不能把前端静态账号展示当作有效登录;写入前先用受保护端点确认会话为 HTTP 200,避免把 HTTP 401 的未落库提交误计为有效回合。
- 2026-07-23 生产回合诊断要在任何服务重启前按当前 MainPID、mount namespace 和 `runId` 精确读取;成功且 `errorCount=0` 时诊断写入器返回 `NOT_NEEDED`,PrivateTmp 无匹配行属预期而非诊断丢失。
- 2026-07-26 认证迁移不能只切换入口与受保护 API;过渡期必须让访问门、服务端鉴权、账户状态展示和退出清理共享同一套双读会话,否则旧用户会出现“能进入但显示未登录”或无法退出。

## 用户数据 / 画像
- 2026-07-28 扩大用户数据收集前,先确认对应主体自己能看到已收集内容——单向不透明的记忆/画像系统是产品信任的硬伤,不是“以后再补”的事项。
- 2026-07-28 “让记录主体看得见”和“让记录主体能删除”是两件不同的事,不能一并给;若该记录会被第三方(如教师)依赖用于判断,记录主体只能查看和申辩,不能单方面销毁——否则第三方看到的会是被筛选过的片面记录。
- 2026-07-28 用户自评/画像类信息只能作为软提示或冷启动默认值,遇到系统实测的权威数据(如诊断档案)必须让位,不得覆盖。

## 数据源 / 契约
- 2026-08-03 内容治理必须把“已获准进入本地知识基线”与“可公开、可上对象存储、可外发给 OCR/embedding/Provider、可商业再利用”分栏记录；后者未知不得反向把前者误标为待准入。
- 2026-08-03 多软件或跨媒介教学不得从工具能力反推固定分工、先后顺序、协议或复现承诺；软件可独立学习，是否整合及其路径应由作品目标、设备条件和实测决定，媒介变化本身也可能成为新体验。
- 2026-07-28 聚合向量索引常用一个不可变张量文件承载许多目标；持久化契约必须把共享 payload 与每目标的 tensor key/offset/count 定位分开，不能强迫逐目标复制文件或拿单个目标冒充整库索引。
- 2026-07-28 一个活动混合索引控制包可能同时封装多个本地 provider；provider manifest/hash 必须按 representation 或 index version 绑定，不能用顶层单值覆盖文本与视觉两个不同的索引身份。
- 2026-07-28 检索评测字段名不能代替实体粒度契约；golden 中的 object、node、asset ID 必须分栏并由规范语料映射，避免把旧对象 ID 当成真实节点 ID 后虚报节点命中。
- 2026-07-28 “同节点双通道共识”必须从候选投影开始保持 node 粒度；先按 object 融合或去重后再比较，无法证明两个通道实际命中了同一节点。
- 2026-07-28 检索排名、父级选择或区域聚合行为只要会影响结果，就必须由版本化配置驱动、进入索引与报告 identity hash，并由实际执行代码读取，不能只把说明文字写进 manifest。
- 2026-07-28 面向召回的宽泛课程域关键词不能兼任 NO_ANSWER 硬守卫；它会把课程内真实问题误拒答，能力边界应在独立 hard-negative 集上显式建模和校准。
- 2026-07-28 在当前评测用例上比较并选出的向量聚合策略只能作为开发/验收证据；即使 identity 已更新，也不能冒充独立 held-out 泛化结果。
- 2026-07-28 课程包竞争诊断应在词法和向量 provider 的同一次查询计算中旁路产出，不能为取全库 winner 再发一次空 scope 请求；后者会改变调用指纹、截止时间和有状态故障注入语义。
- 2026-07-28 多模态检索降级必须按查询模态定义：有文本或受控冻结说明时才能回退词法，纯图片查询在视觉通道不可用时应显式 fail-closed，不能丢掉图片后伪装成成功。
- 2026-07-28 视觉检索评测器只能向模型侧传不透明资产 ID、像素和真实查询上下文，ground truth 与路径映射留在评分侧；命中还须携带语料、索引 bundle、模型 revision 和 representation 的完整版本来源。
- 2026-07-28 视觉检索语料若把答案说明文字排进图片，整图命中可能只是 OCR 泄漏；应在模型运行前冻结不含说明区的像素 bbox，并按案例组而非同图衍生页统计独立样本。
- 2026-07-28 隔离模型 sidecar 不得整包继承 Web 服务环境变量；只传 Windows/CUDA 必需项和显式白名单，否则应用密钥会越过进程信任边界。
- 2026-07-28 图搜图评测必须在线校验并重新编码查询像素；直接复用候选索引中的同资产向量既不能支持新图片，也会从 p95 中抹掉最贵的预处理与推理阶段。
- 2026-07-28 模型 revision 和索引 hash 不能只在构建时写进 manifest；应以模型目录外的 snapshot seal 绑定文件清单，并在加载时重算索引 bundle、核对目录名和全部 tensor 布局。
- 2026-07-28 多 provider 控制包不能只分别验 manifest 与 tensor 文件哈希；还必须交叉核对 manifest 声明的 corpus/model/index/张量哈希与形状确实指向 locator 配对的 tensor payload，否则两个各自合法的文件仍可被错误重组。
- 2026-07-28 有截止时间的 sidecar 请求必须在任何异步像素解析前挂载取消竞态，并在写入子进程前再次验 signal；否则主调用虽已超时，慢解析仍会向模型发出幽灵请求。
- 2026-07-28 Windows 子进程 `kill()` 返回 false 只说明信号未送达，不能单独证明进程仍存活；清理验收应以真实 `exit` 事件和有界等待为准，避免把退出竞态误报成残留进程。
- 2026-07-28 多模态 bundle 中“有 N 条资产元数据”不等于 N 个实体素材可用;激活前必须在任何迁移/写库之前逐文件核对 containment、realpath、类型、字节数与哈希,失败时连数据库文件都不应创建。
- 2026-07-28 带内容哈希的持久化契约必须分开“构建时封装”和“载入时验真”入口；载入时重算后覆盖旧哈希会把篡改伪装成修复，路径字段还须额外拒绝 Windows 设备名、ADS、控制字符和尾随点空格。
- 2026-07-28 多课程知识对象必须把“来源课程身份”和“旧检索放置/namespace”分开保存;用主题枚举反推课程会把跨课程共用主题静默路由到错误课程包。
- 2026-07-28 证据图的 source/owner/parent 映射必须由已验真的规范语料确定性派生;调用方只能声明所需 sourceId,不能借此改写来源身份或用旧检索放置替代来源课程。
- 2026-07-28 检索评测必须把运行时可见的查询上下文与 expected/golden 标签物理分字段保存，检索器只能接收前者；用答案标签预筛候选会静默抬高 Recall 并让跨域负例失真。
- 2026-07-28 多通道检索的对象级共识不能静默改写成节点级共识；应旁路保留对象内真实候选，只在通道交集存在真实节点后进入 exact-node 门禁，并让证据扩展从原始结果重算完整对象排名与有界 fused 前缀，不能只核对单条 trace。
- 2026-07-28 Object Recall 只能证明找到了知识对象，不能证明对象内所需事实已进入证据；评测应另算跨章节原子节点覆盖，多声明问题还要允许同一对象贡献多个支持节点。
- 2026-07-28 路由评测里的 `ANSWERABLE` 只表示问题可进入静态语料检索，不保证问句每个声明都有原子证据；声明级评测必须逐题另建 support qrels，不能把路由标签直接升级成答案充分性真值。
- 2026-07-28 选择对象内重排模型前应先审计原子证据长度、每问最大候选对数和独立支持节点标注；短证据与严格延迟门下，不能因更长上下文或更大参数量直接选更重模型，更不能在没有 qrels 时下载后对着同一结果调参。
- 2026-07-29 A/B 工单写“额外延迟”时必须在看结果前冻结计时边界、重复聚合和差值公式；否则可在模型耗时、整链耗时与两臂差值之间事后切换，门槛就失去审计意义。
- 2026-07-29 检索计划中的 Top-M 默认是候选上限而不是上游一定能交付 M 条的保证；应预先写明不足甚至为零时只用真实可得项、禁止从标签或别的通道回填，并由召回指标暴露上游缺口。
- 2026-07-29 声明级选择器进入模型评分前必须先计算候选池 oracle，且 oracle 要比最终质量门保留明确余量；oracle 等于或低于正式门槛时，继续换重排器既无法证明选择能力，也会把结构性不可达伪装成模型问题。
- 2026-07-29 候选池 oracle 只证明证据存在，冻结选择器前还必须计算“每个必需组是否进入分声明选择前缀”的 selection oracle；若这个上限低于正式门，继续调集合选择或最终 Top-K 同样结构性不可达。
- 2026-07-29 多义务多查询的全局 RRF Top-K 会让单个义务通道中的第一名被其它查询累计分数挤出；应在不增加 provider 调用的前提下先保留每个义务物理查询与健康通道的 rank-one 对象，再按原全局次序补满有界候选池。
- 2026-07-29 查询先决条件应绑定完整用户意图；检索分面只有在独立结果仅为 AMBIGUOUS、可验证为同 scope 静态父问的严格原文子片段时才可继承，显式外部状态或工具动作决策绝不能靠父问绕过。
- 2026-07-30 时间词只能与外部状态请求共同证明实时依赖；“现在越看越乱”这类叙事口语若同时提出静态筛选或设计指导，whole-query 仍应进入课程库检索，不能因单个“现在”被跳过。
- 2026-07-29 设计多查询检索接口时要同时冻结批量入口和查询 scope 来源；只有单条 probe 签名既无法证明物理查询跨查询并发，也无法从不含课程范围的编译查询恢复安全边界。
- 2026-07-29 复用字节冻结但输入合同过时的离线评分器时，应先密封新合同的权威无标签工件，再派生有明确投影审计的兼容桥；不能把新通道伪装成旧字段，也不能让桥接计数冒充真实运行计数。
- 2026-07-29 冻结总超时的真实模型评测必须覆盖 provider client 构造路径并验证 idle timeout 小于 total timeout；fake provider 绿灯不能证明真实客户端可启动，启动前失败要用模型调用数与工件数区别于有效 DEV。
- 2026-07-29 延迟敏感的结构化规划不能继承通用回答模型的默认 reasoning 和自然语言 JSON 提示；应冻结 per-call effort 与 strict schema，并先用无标签最小下界探针区分模型池延迟和 prompt 开销，不能事后改 DEV 门槛冒充修复。
- 2026-07-29 给模型子阶段增加独立 provider 时，必须同时接通环境白名单、完整或回退组校验、安全来源证明和真实消费端；只在服务配置里增加变量会被解析层丢弃或静默继续使用主模型。
- 2026-07-29 中转模型池的模型 ID 可能对空格、连字符和大小写敏感；新增独立模型前应先用专用 Key 查询 `/models` 并原样使用返回 ID，不能凭展示名猜请求值；即使多个别名都出现在模型目录里，也要先用不含项目数据的最小探针逐个验证真实路由健康，目录可见不等于上游实例可用。
- 2026-07-29 语料绑定评测只能证明所选库内能力的检索表现；出题前还应生成知识对象能力清单并报告题集覆盖的对象/节点比例与采样权重，不能把每课程等额的小样本分数解释成知识库整体或课程覆盖率。
- 2026-07-29 评测集按 objectId 隔离仍可能把模板复制品冒充独立能力；冻结划分前应对可评分原子证据做规范化内容指纹和能力家族聚类，重复模板按一组计数，并与图片特异能力分开验收。
- 2026-07-29 模型前的合成评测 fixture 必须复用真实 authoring 的枚举、大小写和跨字段约束，并先走一次已曝光回归入口；自造简化标签会让 schema 漂移拖到昂贵模型运行后才暴露。
- 2026-07-29 跨工作树融合不能把“已有运行报告”当成“已有可复现组件”；先核对合同、代码和 artifact 是否已跟踪提交，再以版本化 port 对接，禁止从脏实验树做运行时 import。
- 2026-07-29 版本化模型工件的校验器不能只接受“当前配置常量”；配置升级后仍须按工件自带的 config hash 从窄白名单验真，否则历史失败工件会因本地代码前移而失去可审计性。
- 2026-07-29 固定 pilot 达门后的 full expansion 若未达门，必须冻结为泛化 NO-GO，并分层报告候选 oracle、原始选择和确定性补齐；不得拿 full 标签继续调同一选择规则。
- 2026-07-29 UI 把多阶段 Agent 流程呈现为“模型思考”时，应只公开可验证的阶段、结果与降级状态，并让 live event 和持久化 trace 同源；不得展示隐藏 chain-of-thought、内部 prompt 或未校验中间 JSON。
- 2026-07-29 多模态查询合同必须区分“用文字检索图片证据”和“用上传图片作为检索输入”；前者的 IMAGE 目标模态不能冒充后者，未实现外部图片像素解析与在线编码前不得宣称支持作品图搜图。
- 2026-07-29 后序 shadow POC 依赖已验证但未生产激活的前序路由时，应使用默认关闭、无原问泄漏且逐次留痕的显式评测 seam；不能改写问句绕过旧门禁，也不能借评测把候选静默激活到生产。
- 2026-07-28 学生用引号标出的评价词不等于技术实体；证据门禁只有在已识别代码、参数、专名或显式引用语义时才能把引号内容当 exact anchor，否则逐字匹配会稳定误拒可回答问题。
- 2026-07-28 查询里出现“文件、尺寸、画布”等上下文名词不等于上下文已经提供；先识别“没有、没给、未提供、缺少”等否定范围，再判断参数问题是否具备前提，否则词面存在会把明确缺失反判成已满足。
- 2026-07-28 故障注入若在一次调用内同步重启 sidecar 并做健康探测，必须把业务超时与恢复证明预算分开；否则模型重载耗时会把正确降级偶发误判成 timeout 回归。
- 2026-07-28 图片检索基线必须逐资产绑定说明并冻结知识、源文与资产的内容摘要；先命中文档再展开兄弟图片会让文件名顺序冒充图片相关度，只有条数和 suite 哈希也不能复现实验。
- 2026-07-27 仓库里可能存在同名同类、看起来都像"正式语料"的多套数据目录,但只有一套真被代码读取;为某个目录批量产内容前,先 `grep` 该路径确认有代码消费它,否则产出再规范也进不了运行时。
- 2026-07-27 判断"某能力是否真的接通",要一路追到消费端而不是停在注册表:枚举、映射表、类型字面量任一处没覆盖新增项,注册看起来齐全但运行时静默为空。
- 2026-07-27 新课程实验台不能只注册 view、adapter、capability 与 course pack;还必须核对专业路由、历史回合恢复、动作 target→adapter 映射和学生端入口,否则代码可编译但导师工具会静默不可达。
- 2026-07-27 给既有校验契约供稿前先读全 `superRefine`/自定义校验:前缀约束、必含默认项、跨字段唯一这类规则不体现在字段类型上,只在加载时抛错,批量产出后才发现要全量返工。
- 2026-07-27 桥接两套不兼容格式时,优先"构建期生成并提交产物"而非运行时转换:产物能在 diff 里逐条复核、现有加载器零改动,并用"重新生成后与已提交产物一致"的防漂移测试兜住。
- 2026-07-27 批量案例语料不能只校验字段齐全与资源存在;还要抽查正文和对应图片是否同一案例,遇到复制粘贴错文应隔离原文并只写可由图像直接观察的关系。
- 2026-07-27 单来源 URL 契约承载不了多站点导航;未扩展 Schema 前应把聚合条目降为不含链接的资源选择方法,不能在转换时静默丢掉其余链接后仍宣称导航完整。
- 2026-07-27 计划要求用附件核验史实时,正文列出论文名不等于附件可得;核验文件缺失就暂缓该史实条目,不能用相邻材料补写。
- 2026-07-30 Agent 的学生输入虽是纯文字，只要工具目标包含课程图片证据，就必须使用明确支持文字搜图的检索模式；把输入模态误当成目标模态会让视觉 provider 合法地 `SKIPPED`，而不是报错。
- 2026-07-30 有界证据投影必须在全部节点、资产、区域和来源裁剪完成后重验引用闭包；分别满足数量上限仍可能留下指向已裁掉资产的悬空节点，必须 fail-closed 而不能交给模型猜。
- 2026-07-30 新检索臂不能把健康 `EMPTY` 直接等同于“无需课程知识”并静默替换旧链；A/B 必须单列证据覆盖率，产品路径则要为未覆盖课程定义可审计的旧链继承或明确降级，否则来源真实性可能提高而回答专业性反而下降。
- 2026-07-31 多通道检索熔断器应包在已适配的 channel provider 外层并按 generation/channel 实例化；这样才能把健康 `EMPTY` 与可恢复故障分开、只降级故障通道并让新代际获得干净状态，放在全局 hybrid 外层会把视觉故障误伤文字与词法。
- 2026-08-04 审核通过后的知识 release 必须冻结精确对象、来源、审核记录与权利/投影范围的哈希；创建版本清单只完成版本封存，不能被解释为已授权投影、索引、活动指针或学生端激活。
- 2026-08-04 知识 corpus 即使对象数量不变，只要 bundle hash 已变化，旧 runtime package、向量、qrels 和活动 generation 就只能视为旧代际证据；必须重建并重新验真，不能用“数量相同”推断索引仍同步。

## 协作 / 流程
- 2026-08-02 跨谱系人工合成同一运行函数时，生命周期审计与业务响应组装属于正交职责；应把新证据逻辑嵌入既有生命周期和重试边界，不能整块选边而丢失审计、截断保护或证据归因。
- 2026-08-02 当 Harness 候选与当前学生端的 UI/API 祖先明显分叉时，自动回归通过也不能作为人工 UI 验收或上线依据；应从已核验的当前 UI 基线新建工作树并只移植窄运行时接缝，不能 rebase 旧候选覆盖产品前端。
- 2026-07-28 并行任务存在脏工作树时，计划必须把“新建独立 worktree”写成立即开工方式而不是前序等待条件；文件隔离不等于功能依赖，否则执行者会误把无关阶段当阻塞门。
- 2026-07-28 给 Durable Web Agent 增加运行中补充或改向时不能只解除输入框禁用；用户消息、意图、顺序、安全降级和后继 run 都必须先由服务端持久化并在原 run 的安全边界后推进，否则刷新或并发会丢指令、重复执行或产生双回合。
- 2026-07-28 规划“本地运行/自托管”能力时必须分别写清 Web 前端交付形态、服务端部署位置和模型执行位置,避免把后端所有权误解为要改成桌面应用。
- 2026-07-28 Windows Playwright 已枚举完用例但没有最终汇总时不能判为通过；应把用例执行与 `webServer` 收尾分别留证、精确管理隔离服务 PID，并只在 runner 正常退出后签收浏览器门。
- 2026-07-28 开发服务器冷编译可能同时超过页面导航预算与多个短探针预算，且被浏览器中断的首次 API 编译不一定能靠同页重试恢复；浏览器门应先预热全部被短探针调用的只读端点、给首次正式路由足够时间，再复用产品的一次重检入口，不能把冷启动误报成登录回归。
- 2026-08-12 私有持久化接手旧版采集包时，应将原始包验真与 canonical 合同升级分开建模；缺失的媒体角色、来源术语或动态证据只能标记待规范化，不能在导入器中补猜。
- 2026-08-10 按独立批准提交执行切片前先验证该 SHA 是否属于当前 HEAD 基线；若不是，必须从精确批准 SHA 建立隔离分支，避免把契约误落到无关主线或被否决候选上。
- 2026-08-09 新增非课程检索源时，不能复用不分域的来源列表；候选、上下文、引用卡和审核/许可门禁都必须按具名知识通道独立建模，默认拒绝未授权或证据不足的素材。
- 2026-08-09 灵感案例的“已审核/许可有效”不是可引用资格；学生受众与范围、安全审核、展示与 AI 引用的行为级许可、撤下状态和对应通道状态必须在同一个服务端合取谓词中逐次 fail-closed。
- 2026-08-09 私有候选的资源引用不是可渲染预览 URL；教师审核界面必须等待经鉴权、可撤销的预览派发契约，不能把内部 locator 放入图片标签、链接或学生端数据。
- 2026-08-09 受控预览必须把“有私有资源引用”与“有可交付字节”分开：在真实私有资产 resolver 落地前，只允许明确登记的本地 synthetic fixture 通过受鉴权预览端点，其余记录显示安全缺图状态。
- 2026-08-09 若游标公开的是脱敏 ID，排序和游标比较也必须使用同一公开排序键；按私有 ID 排序再比较公开哈希会漏页，且不能靠把私有 ID 塞进可解码游标修补。
- 2026-07-22 计划只是初稿:执行方开工前先只读复核,发现缺口就停在生产执行前退回、据实修正后再跑;这道关是流程设计的一部分,不是谁不行。
- 2026-07-28 计划要求给某个实体加字段前必须先确认仓库里的权威持久化主体;若计划中的表并不存在,应把映射显式落到真实主实体并验证全部身份读写链路,不能为迎合文档名称另造重复身份表。
- 2026-07-22 破坏性/不可逆动作(封存加不可变位、切 current、换库)前留人工确认闸门,且失败要能安全回退(先解除不可变位再清理,别直接 rm)。
- 2026-07-22 需要人在终端输密码这类人工介入点,不要靠"再写一批脚本"绕——绕不过去只会空转;识别出人工点就停下等人。
- 2026-07-23 给已有系统做加固前先只读确认目标机制是否已存在并核对真实阻断点,避免重复实现已有状态机而错过更大的故障面。
- 2026-07-26 重试预算不要把总时长提前均分给最大尝试次数,否则首轮被腰斩成 1/N;应“首轮吃满剩余、重试只吃剩余”,快速失败护栏交给“剩余<延迟+最小预算即跳过”。
- 2026-07-26 per-attempt 总超时若小于 idle 超时,会把 idle 保护 clamp 到失效;给满预算同时要确认 idle 超时真的挂到该次流式调用上。
- 2026-07-26 流式打字机的“整段贴”是“按块到达 + 整块渲染”导致;手感靠客户端字符级匀速缓冲(rAF drain)+ 容错未闭合 markdown 的渲染器,与网络块大小解耦,别靠后端攒句。
- 2026-07-26 改 UI 前先确认真实路由(app/**/page.tsx)实际挂载的是哪个组件;被 import/被 Shell 引用 ≠ 被路由,别对着“有引用但未上线”的旧组件做计划(本例 /student 挂 AssistantUiLab,MentorChat 是孤儿)。
- 2026-07-26 持久化流式任务必须区分“用户明确停止”和“前端线程切换/卸载”;后者只能断开本地订阅并可从事件续接，绝不能向服务端发送取消请求。
- 2026-07-26 取消流式回合时，耐久 token 事件本身不足以保证半成品可见；终态历史适配必须从事件重建正文并以“未完成”状态渲染，不能只追加“已停止”的替代文案。
- 2026-07-26 续写上下文只能从服务端持久化的学生可见正文重建并由服务端建立续写关联，绝不能信任客户端自带的源回合或既有文本，否则会把错用户内容、隐藏步骤或重复接缝带入下一回合。
- 2026-07-27 模型协议的终态原因是业务语义而非纯传输细节；遇到输出长度上限必须随正文贯穿客户端、回合契约与续写 UI，不能把已生成内容误判为完整成功或连接中断。
- 2026-07-27 产品改为在断流后保留已收到正文时，端到端评测也必须断言半成品、未完成标记和敏感信息脱敏，且跨重试的正文缓存必须按尝试隔离；否则全量校验会把正确容错误报为回归或把同一前缀重复交付。
- 2026-07-27 流式文本在新 run 重放已显示前缀时，不能只在 render 层保留前缀；rAF drain、空文本分支与重挂载初始化也必须使用同一前缀关系，否则仍会清空或重打。
- 2026-07-27 用户停止与服务端持久化终态可能交错；续写入口要在已有正文可见时同步登记，并以服务端已持久化的未完成记录复核，不能等被取消的前端轮询再补建映射。
- 2026-07-27 对接 assistant-ui 本地 runtime 时要先核对流更新是追加还是替换；若适配层发送全量快照，视图必须稳定地只消费最新快照，否则续写会重复正文甚至触发渲染错误。
- 2026-07-28 本地 UI 验收的截图和可再生成 SQLite（含 WAL/SHM）必须在首次生成前被 `.gitignore` 排除，否则工作区噪声会掩盖真实提交并把瞬态数据带进发布。
- 2026-08-02 Playwright 的 Better Auth 隔离环境必须把 base URL 和 trusted origin 同时固定为同一 loopback host/port；只设应用公开 URL 会让鉴权在到达产品路由前因 origin 校验失败。
- 2026-08-02 开发服务器首次编译动态路由可能触发 Fast Refresh 并丢失瞬态提示；浏览器验收应优先断言重新读取后仍存在的持久化状态与权限结果，不能把 toast 存活当作唯一证据。
- 2026-08-02 为当前 UI 补路由与流式假模型证据时，测试回执必须来自持久化运行结果且默认不展示，假模型还要区分导师流式请求与后台标题请求，避免把标题调用误计为重试或主回合。
- 2026-07-30 会扫描完整冻结语料和资产清单的集成型单测，在全量并发下可能超过 Vitest 默认 5 秒而单跑明显更快；先用相同用例定向复现区分逻辑失败与资源争用，确认断言和数据量不变后再给该用例显式墙钟预算，不能靠重复全量运行碰运气。
