- 2026-08-11 动态/交互作品的作品形态必须与采集到的证据媒介分开建模；静态封面只能作为降级预览，不能证明运动、交互、声音或实时行为，行为声明须绑定动态媒体或来源陈述并标注证据覆盖程度。
- 2026-08-12 原始候选元数据只能作为治理材料；只有受控图组、作品—原始来源匹配、来源角色、权利证据、规范化分类、视觉描述、重复关系及策展/教学建议全部由严格合同绑定后，才可计入教师审核队列。
- 2026-08-12 权利证据门表示使用边界已经查明，不表示获得正式发布授权；站点分享条款与作品页作者版权并存时，可把未改动素材限制在教师私有复核，并把再发布决定继续保持 `UNKNOWN`。
- 2026-08-12 网络资产包通过摘要、解码和索引校验后仍不能直接成为受控图组；派生 ReviewPack 前必须隔离站内广告、低分辨率变体与跨作品共享情境图，并保持原始交付包不可变。
- 2026-08-12 来源角色必须按具体页面及其署名事实判定，不能按整个域名硬编码；同一站点可能同时承载官方作品页与策展记录。
- 2026-08-12 图片放大器的导航控件应与可滚动、可裁剪的媒体舞台分层；仅提高 `z-index` 仍可能让移动端原生指针事件落到画布而非按钮。
- 2026-08-12 大批量 ReviewPack 应让机械构建器从不可变索引补候选 ID、尺寸、哈希、预览路径和关闭边界，但来源、权利、视觉、策展与教学语义仍须逐项审计，不能由模板自动升格。
- 2026-08-12 审核队列汇报必须区分累计严格 ReviewPack、当前待教师审核与已进入私有 WikiDraft 的数量，并在每批导入后从数据库重读状态，不能沿用先前快照。
- 2026-08-12 产品允许缺证素材先交人工判断时，应新增显式的证据缺口审核对象与状态，逐门保留 `MISSING/UNVERIFIED`，不能放宽严格合同或把人工接受缺口反写成九项齐备；后续正式发布仍需独立门禁。
- 2026-08-12 公开图片的响应 MIME 与实际字节格式冲突时，不能把可用素材直接归类为“无图”；应在受控来源与安全重定向边界内，以文件魔数、真实解码、尺寸和哈希联合验真，并把响应头异常保留为审计事实。
- 2026-08-12 对退回、拒绝等需要理由的教师动作，不要用无说明的禁用按钮隐藏前置条件；应允许点击后就地说明必填原因并把焦点移到对应字段，同时让服务端继续执行同一硬校验。
- 2026-08-12 已审核结论需要再次编辑时，应以当前审核 revision 做并发校验并追加一条新决定，预填上次判断且保留原审计记录；不能原地覆盖第一次决定，也不能因此打开发布或学生能力。
- 2026-08-12 教师界面的证据材料应通过独立本地化显示层提供中文，保留原始标题、署名、URL、证据正文与 material hash；不得为了汉化直接改写不可变 ReviewPack。
- 2026-08-12 产品明确允许教师对未知来源、角色与权利先行判断时，`UNKNOWN` 必须是独立的已确认事实状态，不再进入草稿动作的缺口勾选或必填说明；退回和拒绝仍须记录理由，发布门禁继续关闭。
- 2026-08-12 艺术表现风格不能用作品类别或普通画面描述代替；应使用受控词表标注风格取向，并另存与可见图像绑定的判断依据。
- 2026-08-12 审核动作中的 `PRIVATE_WIKIDRAFT` 只是候选状态，不能冒充已经存在的可编辑草稿实体；编纂层必须独立保存可编辑物料、来源决定绑定、revision/hash 与追加式编辑历史，并继续与 canonical Page/Revision/Compiled Truth 分层。
- 2026-08-12 同一产品的教师端与学生端需要配色一致时，应把当前可见工作台色板提升为共享语义 token 并让两端共同引用，不能复制一组“近似色”后各自演化；危险等语义色仍须独立保留。
- 2026-08-13 可编辑私有草稿的教师四域预复核必须与正式 canonical 角色治理分表、分合同；前者可追加修订并确认未知权利的私有边界，但不能生成正式角色决定、内部目录或发布资格。
- 2026-08-13 当现有 canonical S1 权利合同无法表达 `UNKNOWN_PRIVATE_ONLY` 时，内部目录准入必须走加法式私有治理合同：绑定真实教师、显式域角色、当前人工决定和精确 Page/Truth 哈希，禁止把未知改写为 `ALLOW` 或用伪造多人身份补齐职责分离。
- 2026-08-13 跨阶段合同绑定上游哈希时必须复用上游的精确编码规则，不能因新层自己的审计哈希带 `sha256:` 前缀就给被引用的 64 位内容摘要补前缀；隔离数据库应同时验证格式和真实阶段衔接。
- 2026-08-13 当一批私有预复核只需人工判断一个领域时，其他领域应根据教师的明确批量确认生成逐项追加决定，界面再聚焦目标域批量分流；不能仅隐藏未判断字段或把私有批量确认冒充正式分域治理。
- 2026-08-13 当内部目录已完成但正式发布仍受权利或范围授权阻断时，下一步应先生成逐项只读发布准备审计并保持通道关闭；不能把“继续执行”或私有准入自动解释为学生可见授权。
- 2026-08-13 用户授权继续推进发布流程只能满足操作范围与发布角色签核，不能替代逐作品的学生展示权利依据；正式 Release 必须同时绑定授权操作、作品权利和可撤回通道状态。
- 2026-08-13 将设计完成的浏览页接入真实 API 时，加载、错误和零结果必须留在同一页面框架内，不能提前返回成另一套简化页面；嵌入既有工作台时还须明确唯一导航归属，避免外壳与内页重复顶栏。

## SQLite / 数据备份
- 2026-07-22 只读打开 WAL 模式库(`?mode=ro`)仍会在库所在目录生成 `-wal/-shm`,污染快照目标目录;读备份/restore point 一律先 `cp` 出副本、再用 `?immutable=1` 打开,绝不就地打开。
- 2026-07-22 备份/restore point 创建并验证后要物理封存(`chmod a-w` + `chattr +i`),否则任何后续读取都可能往里加文件、破坏文件集不变量;清理封存目录前必须先 `chattr -i`,否则连 root 都删不掉。
- 2026-07-22 判断"备份主库是否被改坏"用「现算 sha256 == manifest 登记值」为硬门槛,再用备份目录**之外**的 verified marker 做外部锚点;别假设某个 result 文件里有你需要的字段。
- 2026-07-22 更稳的做法是让备份产物天生就不是 WAL 模式(`VACUUM INTO`,或 checkpoint 后 `journal_mode=DELETE`),从源头免掉旁生文件问题,连 `immutable` 都不用操心。
- 2026-07-26 备份包装器与发布器必须共享同一套封存权限契约;若一方把恢复点设为更严格的目录模式和不可变位、另一方却只接受固定模式,后续备份会在已创建并验证新恢复点后仍持续误报失败。
- 2026-07-28 SQLite 表重建迁移必须逐项复核旧表复制列、生成列和手写触发器是否被正确保留,测试夹具也应始终显式列出插入列,避免加列后位置式 `INSERT ... VALUES` 全面失效。

## 脚本 / 校验
- 2026-07-22 校验里字符串匹配要精确到字段:`lsattr -d DIR | grep 'i'` 会因路径含字母 i 而假阳性;应 `lsattr -d DIR | awk '{print $1}'` 只取属性列再判 `*i*`。
- 2026-07-22 给远程/生产写的脚本,验收断言要打印**可见证据**(不能"成功即静默"),否则事后无法复核。
- 2026-07-22 `systemd-run` 不带 `--wait` 只证明"任务已提交",不证明"任务成功";要同步结果用 `--wait --pipe --collect`,让退出码穿透回 SSH。
- 2026-07-24 `systemd-run --collect` 回收 unit 后,`systemctl show` 对已不存在的 unit 可能返回默认 `Result=success`;部署成败必须以 journal 中实际进程退出状态和阶段证据为准,不能把防御性回收参数制造的假信号当成功。
- 2026-07-23 pnpm 11.7 在跨目录复用 `node_modules` 且无 TTY 时,默认 `verify-deps-before-run=install` 会在脚本前尝试重装并中止;仅对该次命令显式设 `pnpm_config_verify_deps_before_run=false`(或 `warn`)跳过,禁止改配置文件或重装依赖。
- 2026-07-23 发布评测/验收应在 HEAD 精确等于生产提交、Git clean 且 `node_modules` 绑定同一不可变发布版的独立可写目录运行,既避免污染不可变安装目录,也让报告天然绑定正确源码版本。
- 2026-07-23 短探针或案例级模型辅助率不能直接外推真实大回合的通道失败率;A/B 必须使用同一长输入与长输出、按完整 SSE 终止严格判定,并分别统计协议失败和在线超时。
- 2026-07-23 流式模型诊断不能只落聚合协议码和成功输出长度;至少保留原始 cause、比较分支、三路文本长度与归一化/前后缀指标及终止 output item types,否则会把“终止包仅有 reasoning、message 缺失”误判成普通文本差异。
- 2026-07-23 做 `toolChoice` 单变量对照时,`auto` 必须携带与生产按上下文筛选后一致的非空工具 schema,并把 `function_call` 响应与无工具纯文本分层统计;空工具的 `auto` 等价于 `none`,会制造伪结论。
- 2026-07-23 流式失败策略若依赖“首个文本增量前/后”的时序,诊断必须显式记录已发出 delta 的次数与字符数;仅凭协议错误码和总耗时无法事后还原时序。
- 2026-07-23 模型调用重试包装器为统计 delta 生成回调时,必须只在原调用已启用流式输出时注入;无条件注入会把非流式请求静默改成流式协议。
- 2026-07-24 受控部署不能把阶段状态、health 错误和退出码依赖 SSH stdout 管道(`tee`);必须先落盘且让断管输出可丢,否则连接重置会把真实失败伪装成无证据。
- 2026-07-24 跨目录发布权限同步应由单进程遍历并按可运行旧版逐项复制模式,避免逐路径启动外部命令把构建耗时放大到不可接受。
- 2026-07-24 封存动作要匹配目录的归属方:对备份 wrapper 自己创建并需再次验收的目录,只加 `chattr +i`,不要 `chmod a-w` 把 wrapper 要求的 700 改成 500;immutable 已足够阻止写入,后者是零增量的冗余保护。
- 2026-07-24 跨 worktree 用 junction 复用 `node_modules` 会让轨道隔离失效,使测试实际依赖另一轨道且任一侧变更可能波及对方;每条 worktree 应各自安装依赖,或至少确认链接明确指向自身依赖目录。
- 2026-07-24 `git bundle verify` 需要一个现有 Git 仓库作为对象上下文,不能在 systemd 临时任务的无仓库工作目录里当作独立文件校验器;部署入口应先核对 bundle 的精确 ref/SHA,再让 `git clone` 完成 pack 完整性校验。
- 2026-07-25 发布脚本在收紧 release 权限后不要再让服务账号从该目录调用包管理器元命令;Corepack 会读取当前项目 `package.json`,文件尚未恢复可读位时会因 `EACCES` 中止。
- 2026-07-25 发布预检不能只检查构建产物和依赖目录;systemd `ExecStart` 引用的源码入口也必须按服务账号实测可读,否则会在切换后才暴露 `ERR_MODULE_NOT_FOUND`。
- 2026-07-26 Composer 能力筛选与单轮外部工具授权是两条独立门禁;未显式选择能力时仍须保留已经确认的授权工具,显式选择后才按该能力白名单收窄,避免 UI 分类误伤原有安全授权链。
- 2026-07-26 生产模式浏览器 E2E 若直连应用而绕过受信代理,必须在每个用例开始动态签发代理来源头并覆盖登录与写操作,且登录后的鉴权断言要走浏览器内请求以保留 Secure 会话,不能复用过期静态签名或独立无会话请求上下文。
- 2026-07-26 构建脚本若会切入临时工作目录，必须在切换前把输入和输出路径规范为已校验的绝对路径；相对输出会被误写进临时目录并在 cleanup 时静默丢失。
- 2026-07-28 时间敏感或高成本测试的确定性参数（业务时钟与专属超时）必须按最坏完整套件场景显式注入，不能依赖系统当前时间或单文件耗时基线。

## 部署 / 生产状态
- 2026-08-13 内含原始字节摘要的发布包必须为文本工件显式锁定 `eol=lf`、为媒体工件锁定 `-text`，并对真实 `git archive` 成员重算摘要；否则 Windows 导出过滤可在不改 Git blob 的情况下把 LF 改成 CRLF，导致生产导入器正确拒绝。
- 2026-07-22 线上状态值(如 `current` 指向哪个 release)一律以服务器现场 `readlink -f` 实测为准,不信脚本里硬编码的假设值——回滚失败后实际状态可能和脚本预期相反。
- 2026-07-24 发布构建若沿用 `umask 077`,会让 `.next`/`node_modules` 的目录和文件仅 root 可访问;切换前必须显式恢复服务账号所需的 group 读/执行权限,并按实际 `User/Group` 做候选 release 预检。
- 2026-07-22 自动回滚判断"备份能不能用"要基于封存哈希清单(旁生文件改不了主库哈希),别在回滚路径上跑会因自污染而中止的 in-place 校验,否则回滚会被自己造成的污染卡死。
- 2026-07-22 高危流程的目标形态是:单次 sudo、同步等待、阶段状态机(每阶段落盘可续跑)、attempt 作用域证据(每次一个 runId,不覆盖、可幂等重试)、失败自动回滚;否则"异步提交→下轮查结果→失败起 r2"会退化成反复输密码的空转。
- 2026-07-27 免密发布权限绝不能直接指向用户可写脚本或任意服务器输入;必须由 root-owned 固定入口验证签名与哈希并把 prepare 和 cutover 分开,否则“少输密码”会变成普通账号可利用的服务或特权升级。

## 生产浏览器验收 / 诊断
- 2026-07-23 未命名会话首回合在主回合持久化后可能再触发独立的自动标题模型调用;主回合 `aiMode` 应以持久化消息与 runtime events 判定,页面总耗时和模型请求总数不得与预命名 smoke 严格对比。
- 2026-07-23 生产浏览器 smoke 不能把前端静态账号展示当作有效登录;写入前先用受保护端点确认会话为 HTTP 200,避免把 HTTP 401 的未落库提交误计为有效回合。
- 2026-07-23 生产回合诊断要在任何服务重启前按当前 MainPID、mount namespace 和 `runId` 精确读取;成功且 `errorCount=0` 时诊断写入器返回 `NOT_NEEDED`,PrivateTmp 无匹配行属预期而非诊断丢失。
- 2026-07-26 认证迁移不能只切换入口与受保护 API;过渡期必须让访问门、服务端鉴权、账户状态展示和退出清理共享同一套双读会话,否则旧用户会出现“能进入但显示未登录”或无法退出。

## 用户数据 / 画像
- 2026-07-28 扩大用户数据收集前,先确认对应主体自己能看到已收集内容——单向不透明的记忆/画像系统是产品信任的硬伤,不是“以后再补”的事项。
- 2026-07-28 “让记录主体看得见”和“让记录主体能删除”是两件不同的事,不能一并给;若该记录会被第三方(如教师)依赖用于判断,记录主体只能查看和申辩,不能单方面销毁——否则第三方看到的会是被筛选过的片面记录。
- 2026-07-28 用户自评/画像类信息只能作为软提示或冷启动默认值,遇到系统实测的权威数据(如诊断档案)必须让位,不得覆盖。

## 协作 / 流程
- 2026-08-02 跨谱系人工合成同一运行函数时，生命周期审计与业务响应组装属于正交职责；应把新证据逻辑嵌入既有生命周期和重试边界，不能整块选边而丢失审计、截断保护或证据归因。
- 2026-08-02 当 Harness 候选与当前学生端的 UI/API 祖先明显分叉时，自动回归通过也不能作为人工 UI 验收或上线依据；应从已核验的当前 UI 基线新建工作树并只移植窄运行时接缝，不能 rebase 旧候选覆盖产品前端。
- 2026-07-28 并行任务存在脏工作树时，计划必须把“新建独立 worktree”写成立即开工方式而不是前序等待条件；文件隔离不等于功能依赖，否则执行者会误把无关阶段当阻塞门。
- 2026-07-28 给 Durable Web Agent 增加运行中补充或改向时不能只解除输入框禁用；用户消息、意图、顺序、安全降级和后继 run 都必须先由服务端持久化并在原 run 的安全边界后推进，否则刷新或并发会丢指令、重复执行或产生双回合。

- 2026-08-03 多模态证据的 source anchor 必须描述原始容器本身：PDF 单页即使展示多张书籍跨页案例图，锚点仍是 PAGE，页内案例只能作为内容特征或另建 region anchor，不能偷换成 SPREAD。
- 2026-08-03 `VISUAL_PRIMARY` 或 `OCR_PROHIBITED` 只禁止自动全文转录和文本语料化，不等于忽略肉眼可辨的标题、段落块及其位置；这类文字可作为视觉线索，但精确文案、作者意图和独立案例主张仍需单独证据锚点。
- 2026-08-04 已提交的证据或教学草稿在新增可见标签、区域锚点或审核语义后也应生成新对象版本并保留 supersedes/review 链；不能因其尚未发布就静默覆盖旧草稿，从而让退回原因和后续批准无法重放。
- 2026-08-04 同一单页 OCR 能可靠读出标题/索引却漏掉可见主段落时，不能借视觉关系或旧草稿补全其语义；应保留原页与 raw extraction，并将该页明确标为不采纳，直到文字主依据可重放。
- 2026-08-04 文字主依据可由逐区域、可重放的视觉直读补充 OCR，但必须明确来源通道、可读范围和不确定项；布局本身仍只能佐证，不能补写未读文字。
- 2026-08-04 人工认可新的 K6 草案不等于可跳过 K7 review package 直接进入 K9；认可记录、K7 闭包和可发布版本必须保持独立、可回放的状态转换。
- 2026-08-04 试点选页预览必须同时登记 PDF 页码与画面可见印刷页码；二者不相同时不得仅用其中一个作后续锚点。
- 2026-08-04 `MIXED_DEFAULT_ROUTE` 不是把视觉与文字混为单一证据；每一页仍须分别绑定 OCR、视觉直读和视觉观察，且由逐项交叉复核决定各自的语义角色。
- 2026-08-04 页级记录若由闭包根验证器重放，证据路径必须以闭包根为基准并在校验中实际读取哈希；仅检查 JSON 字符串会掩盖多退或少退目录的闭包逃逸。
- 2026-08-04 案例页即使证据可靠，也应把“可解释/可比较”与“可直接指导下一步”分开建模；没有任务相关且直接可操作的依据时，案例不得默认挤占行动型回答位置。
- 2026-08-04 K7 审核包应只读绑定每页的 render、raw OCR、视觉补充和 K6 语义版本，并把 `PENDING_HUMAN_REVIEW` 与任何已批准状态严格分开，避免把准备包误当作 K8 决定。
- 2026-08-04 面向人工的 K7 主入口不能只交付 JSON 或结论表；还应以可直接阅读的 Markdown 逐项并列来源页、简短文字证据摘要、所得知识、视觉佐证边界和非决定性的审核建议，同时保留机器可校验底稿。
- 2026-08-04 多语言知识闭包必须把可追溯的原文证据与学生或审核可见的加工输出分层校验；加工字段以中文为主，专业术语首次采用 English term（中文术语），且下一阶段门同时要求中文化与原文可回链。
- 2026-08-04 KPL 的 K12 若在正式定义中等同 ACTIVE，局部 shadow 验证即使全部通过也必须封存为 K12_PRE_ACTIVATION_READY；不得把本地 gate 伪装成激活、指针写入或学生可见状态。
- 2026-08-04 K12 激活前必须先证明候选 generation 满足真实 loader 的 formal corpus、index 和存储行契约；独立 shadow bundle 不得直接写入活动指针，无法兼容时应在写前 fail-closed 并记录无需回退的审计结果。
- 2026-08-08 K12 本地隔离激活只有在正常产品运行时显式绑定同一 corpus/index/provider generation 后才是可部署生产候选；若新哈希只存在于审计工件而未被在线 loader 引用，部署前审查必须 fail-closed。
- 2026-08-08 活动知识 generation 的切换是整代替换而不是增量追加；新批次生产候选必须先与当前保留语料做对象、节点和资产身份闭合的加法聚合，否则单独激活新批次会静默移除既有 V2 知识。
- 2026-08-04 正式 V2 corpus 若有意不生成 legacy Markdown 投影，存储写入、索引写入和 active loader 都必须显式声明同一隔离契约且默认继续强制 legacy parity；只在其中一层放宽会造成激活后 loader 失败。
- 2026-08-04 本地 lexical-only V2 generation 不应伪装为 provider-backed 混合运行时；学生 turn 应通过既有 evidenceSearchV2 窄注入口消费只读 lexical port，并把 vector/visual 明确标为不可用或跳过。
- 2026-08-07 MinerU 在文件上传后可短暂返回 `waiting-file`；轮询器须把它和 `pending`/`running` 同作正常非终态，进程若在未持久化句柄时退出仍须按远端状态未知闭锁，禁止盲重传。
- 2026-08-07 多账号并行解析只能按不同物理页段分配固定安全环境变量；每段必须有独立在途哨兵和内存任务句柄，成功结果先合并为完整原始闭包，闭包未齐不得启动 K6–K9。
- 2026-08-07 并行异步解析器的在途哨兵必须随提交、上传、轮询、下载和本地固化阶段更新，聚合失败也要保留每段脱敏类别；若已出现完整下载暂存包，应先做纯本地闭包验证，不能仅凭旧哨兵阶段误判远端未知或盲目重传。
- 2026-08-07 结构化解析结果可能为未生成资源的表格留下空 `img_path`；验证器应把空值记录为页级提取异常并禁止其升格为证据，而不是把它当成相对路径逃逸或伪造缺失图片。
- 2026-08-07 异步 Provider 合同扩展正常状态集合时，必须在同一变更中同步机器验证器与可读契约；否则历史验证器会把新合法状态误判为失败，掩盖真正的队列问题。
- 2026-08-07 Windows 上持续读取状态 JSON 可能短暂阻塞同路径原子重命名；并发批处理的审计写入应对 `EPERM`/`EBUSY`/`EACCES` 做有限重试，监控读取也不能成为业务槽失败原因。
- 2026-08-07 用 pypdf 从含复杂批注的长 PDF 拆段时，逐页 `add_page` 可能极慢或失败；应优先采用区间 `append`、复核输出页数，并把底层命令异常收束为脱敏拆分错误类别。
- 2026-08-07 受限 Windows worktree 可能无法写入外置 Git 元数据的 `sequencer/index.lock`；跨路集成时先做来源目录级字节校验，再用受控 Git 权限暂存/提交，不能把元数据写锁失败误判为工件内容失败。
- 2026-08-08 在干净 Git 导出目录复现生产构建时，不能把 `node_modules` 链接到文件系统根外后交给 Turbopack；Webpack 长构建也必须用产物持续写入、有限窗口和最终 `BUILD_ID` 判定，停滞不得误报为成功或无限重试。
- 2026-08-08 未切换候选若需复用生产模型配置刷新质量门，必须以 release 内 root 封存的 source binding 运行并先封存报告哈希；生产报告只可在 cutover 已开始后原子提升，失败时须与代码指针和环境开关共同回退。
- 2026-08-09 Next/Turbopack 发行包不能只验证顶层原生依赖；还必须保留并重放 `.next/node_modules` 中被 `.nft.json` 引用的哈希外部模块别名，并从真实 Next 解析位置加载原生包，否则直接 `require(better-sqlite3)` 通过仍会在健康路由中缺模块。
- 2026-08-09 第三方视觉素材的“可检索”与“可展示/公开”是不同许可；来源版本、处理范围、可见性和撤下传播必须分开建模，并先于向量化或缓存启用。
- 2026-08-09 对非公开、用户提供或尚未经过逐来源 intake 决策的素材候选，入库契约只能允许登记官方元数据；下载、派生、embedding、展示和 AI 引用必须分别获得行为级决定，私有分析许可绝不能被误作发布许可。
- 2026-08-09 同一对话入口不代表知识库或证据语义可以合并；每轮路由、引用资格、输出类型和失败降级必须分库判定，视觉相似只能作为召回信号。
- 2026-08-09 受保护页面的条目数据不能同时放在 `public` 或客户端静态模块；路由服务端门禁必须先于数据序列化，且需实测未登录重定向与旧静态 URL 不可访问。
- 2026-08-09 允许宽进的第三方视觉候选必须物理隔离在私有候选存储中，并由显式状态机阻断学生端、对话上下文与公开路径；候选下载或分析完成不等于可发布。
- 2026-08-09 自动化采集/视觉分析只能产出可解释的候选信号和教师审阅包；把质量、新颖性、教学价值或权利结论自动事实化会绕过唯一人工审核关口。
- 2026-08-09 审批后自动入库必须把期望 revision、幂等键、审核决定、每一步状态迁移和撤下后的索引移除放在同一事务审计链中；仅靠前端按钮或最终 ACTIVE 标记无法防并发越权与旧索引泄漏。
- 2026-08-09 教师审核队列与受控预览必须复用同一数据库级身份和案例可审资格谓词；仅凭角色或临时 cookie 不足以避免失效教师或已冻结/撤下候选从旁路读取。
- 2026-08-09 隔离 worktree 用 `--ignore-scripts` 离线恢复依赖后，涉及原生模块的集成测试仍须单独验证本机匹配的 C++ 工具链与 Node 头文件；不能借用其他 worktree 的 `node_modules` 来掩盖运行时缺口。
- 2026-08-09 审核通过、内部索引激活与正式学生发布必须是独立持久化决定；正式发布用数据库约束要求受众、展示、来源披露、教学、安全、质量、撤下和全部学生通道同时明确通过，旧 cookie 与半开门组合均 fail-closed。
- 2026-08-09 原生依赖的全局预构建缓存若因隔离权限不可写，可把锁定包版本与当前 Node ABI 精确匹配的既有缓存复制到 worktree 本地 cache，再用仓库锁定包管理器离线恢复；最终仍以实际加载原生 binding 的探针和集成测试为证据。
- 2026-08-09 新增持久化表时必须同步维护迁移全表清单断言并跑全仓测试；目标路由回归通过不能证明迁移后的规范 schema 清单仍完整。
- 2026-08-10 采用 LLM Wiki 时必须把 canonical 治理真相、可重建 Wiki 编译投影和未来向量旁路分层；某现成检索器替换旧知识库的评测结论不能外推为该方法论不适合独立知识产品。
- 2026-08-10 在既有系统上更换知识架构时，应把已验证的身份、审核、发布合取门和安全投影当作可复用外壳，把派生 read model 与检索器列为可替换核心；否则会为了“重做检索”重复造安全能力或让旧检索语义偷偷存活。
- 2026-08-10 多域审核不能把“教师”当作通配权限：角色域、自审限制、需要时双人复审及精确 revision/hash 必须写入决定与上线复查；候选审核预览和学生发布预览也必须使用互斥 resolver，禁止跨身份链 fallback。
- 2026-08-10 审核人撤权传播必须按该 assignment 实际参与的已接受决定精确定位受影响产物，再逐项重跑当前性门禁；不能按共享 policy revision 批量冻结所有条目。
- 2026-08-10 跨对象授权链不能只让每个对象各自通过 schema、也不能让一组 caller-supplied hashes 相互自证；哈希只能证明绑定与完整性、不能把 `DENY/WITHDRAWN` 变成授权，expected identity 与权限/撤下/provenance 语义必须从严格分型 canonical material 单向重算，再让审核目标、Page/Revision、release/current、timeline/link/index 与 receipt 逐跳绑定，并用全量重哈希负例证明 A 的授权不能借给 B。
- 2026-08-10 标称纯函数若直接递归冻结入参仍会修改调用方状态；应先复制 JSON 值再冻结新输出，并用调用后仍可修改原对象且不影响输出的测试固化边界。
- 2026-08-10 派生索引只证明构建时物料有效；查询当前性必须由受控上游提供有限期、绑定 exact index/Page/review/rights/withdrawal 的 allowlist receipt，查询只能收窄并复查静态到期，caller 传入的 eligible IDs 或自行计算的哈希都不构成授权。
- 2026-08-12 E2E 验收必须从当前 canonical 登录页和主会话机制进入；旧邀请码/访问码会话只可覆盖迁移兼容性，不能替代邮箱密码登录的产品验收。
- 2026-08-12 “证据缺口”只能弱化对应的未知门，不能把已完成分析折叠成简化卡片；教师端仍应完整呈现分类、艺术风格、视觉观察、重复关系、策展与教学内容。
- 2026-08-12 教师退回的视觉纠正必须通过 revision CAS 和追加式物料审计重新送审，不能直接覆盖旧描述或清除原教师决定；重开队列时来源、权利与学生/发布能力边界不得被顺带提升。
- 2026-08-13 私有编译产物必须使用 `PRIVATE_COMPILED_PREVIEW` 并把“最新私有修订”与正式 Current Page 指针分开；即使四域均通过，也不能借用 `CURRENT_COMPILED_TRUTH` 名称或写入正式 S1 表来暗示已发布。
- 2026-08-13 新旧学生灵感通道并存迁移时，应以独立只追加 Shadow 快照作为显式闸门：存在 Shadow 即阻断学生暴露，只有未来绑定完整正式发布资格的 Active 快照才可读取；无快照时旧轨才按原合同回归。
- 2026-08-13 合并长期分叉的 SQLite 迁移链时，不能只按文件名冲突顺延；必须从实际数据库 journal 反查最早分叉点，把缺失生产迁移与本地 schema 归并到新编号，并用空库、旧分叉库和生产前缀库三路重放验证。
